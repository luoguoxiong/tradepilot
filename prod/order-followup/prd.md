## 1. 背景与目标

一期「客户开发」解决把客户找进来；二期「跟单助理」解决客户进来之后的事：外贸业务员在手订单 10~50 个，订单信息散落在邮件/Excel/微信里，单证手工做、交期靠脑子记、催货常常忘。本模块将订单录入、单证制作、进度跟踪、提醒催货、客户通知压缩到以分钟计。

成功标准（v1 验收口径）：
- 订单录入：1 笔订单从上传到入库确认 ≤ 2 分钟（人工仅做字段核对修正）
- 单证生成：PI/Invoice/PL 从订单到成品 ≤ 1 分钟，关键字段 100% 溯源自订单
- 提醒：交期前 N 天/逾期订单 100% 出现在异常看板，零遗漏
- 邮件：草稿采纳率（发送前仅轻微修改）≥ 80%

## 2. 目标用户与场景卡

| 项       | 内容 |
| -------- | ---- |
| 用户画像 | 外贸一线业务员 / SOHO，单账号使用（与一期同一用户群）；在手订单 10~50 个，客户 20~100 家 |
| JTBD     | 「当我接过客户定金/订单后，我想让系统帮我记住每个订单走到哪一步、什么时候该催工厂、该给客户汇报什么，以便不出错、不逾期、不冷落客户」 |
| 环境     | Web 浏览器；订单文件来自客户邮件附件（Excel/CSV/文本型 PDF）或聊天记录粘贴；有自备 SMTP 邮箱 |
| 明确不做 | 多用户/权限、IMAP 自动拉单、物流 API、报关单证、图片型 PDF 解析 |

## 3. 核心用户流程（人机协同）

```text
① 上传订单文件（Excel/CSV/PDF文本/邮件文本粘贴）
        ↓
② AI 解析抽取订单字段（带置信度标注）→ 用户核对/修正 → 确认入库
        ↓
③ 订单台账（列表+详情：客户、产品行、金额、币种、付款方式、贸易术语、关键日期）
        ↓
④ 订单详情页内：
   a. 进度节点更新（手动：下单确认→定金到账→工厂下单→生产中→验货→出货→发运→收尾款）
   b. 一键生成单证：PI / Invoice / Packing List（模板渲染+校验+人工确认，导出/打印）
        ↓
⑤ 系统定时检查（交期前 N 天、逾期、定金未到、长期无进展）→ 异常看板聚合
        ↓
⑥ 从异常/详情页一键生成邮件草稿：
   - 给工厂：交期提醒/催货函
   - 给客户：订单进度汇报
   → 人工编辑 → 确认 → SMTP 发送 → 记录留痕
```

人机协同点：② 字段确认、④a 进度手动更新、④b 单证确认、⑥ 邮件确认发送。
AI 职责：② 字段抽取、⑥ 邮件草稿生成、④b 单证字段填充建议（仅填充，不造数）。

## 4. 功能需求

### F1 订单导入与 AI 解析

- 上传/粘贴通道：Excel(.xlsx/.csv)、文本型 PDF、纯文本粘贴（邮件原文/聊天记录）。
- AI 抽取字段（输出 JSON，附逐字段置信度）：订单号/PI号、客户名与邮箱、下单日期、交期、贸易术语（Incoterms 2020）、付款方式（T/T 定金比例+尾款、L/C、DP/DA）、币种、总金额、产品行（品名/型号/数量/单位/单价/金额）、唛头、备注。
- 低置信度字段（<0.7）标黄，缺失字段留空要求人工补填；**解析结果必须经「确认入库」才能建单**；解析失败自动转手动录入表单。
- 同一订单重复导入按订单号去重提示。

### F2 订单台账

- 列表：状态（正常/待办/逾期）、客户、订单号、金额/币种、交期、当前节点、剩余天数排序。
- 详情：基本信息 + 产品行表 + 时间线（节点更新历史）+ 关联单证 + 关联邮件 + 操作（更新进度/生成单证/发邮件/标记异常处理完成）。
- 手动录入表单（与解析结果共用同一数据结构）。

### F3 单证生成（PI / Invoice / Packing List）

- 架构红线：**模板引擎渲染 + 订单结构化字段填充 + 校验器，禁止 LLM 自由生成数字**。
- 校验器规则：数量×单价=行金额、行金额合计=总金额、大小写金额一致、买卖双方信息完整、PI 与订单号对应、唛头一致；校验不过则阻断导出并高亮问题字段。
- 输出：HTML 单证（A4 打印样式），支持浏览器打印/存 PDF；单证快照落库（版本留痕，改单后新旧可对比）。
- 字段允许发送前人工微调，微调需注明原因并留痕（不改订单源数据时给出「同步回订单」提示）。

### F4 进度跟踪

- 固定节点模板：下单确认→定金到账→工厂下单→生产中→验货→出货→发运→收尾款（可跳过不适用节点）。
- 每次更新：节点、日期、备注；时间线展示；当前节点驱动异常判定。

### F5 交期提醒与催货（异常引擎）

- 定时扫描（服务端 interval，默认每 30 分钟）+ 每次打开看板时实时计算。
- 规则（可配置）：交期前 N 天（默认 7/3/1）提醒；交期已过未出货→逾期；定金节点超过 X 天未更新→定金跟进；订单创建后 Y 天无任何节点更新→停滞提醒。
- 异常看板：按类型聚合（交期临近/逾期/定金未到/长期停滞），一屏展示待办动作入口。

### F6 邮件：进度汇报 / 催货函

- AI 生成草稿：上下文 = 订单信息 + 当前进度时间线 + 异常类型；客户进度邮件（默认英文）礼貌专业、要点化；工厂催货函明确交期与后果表述、语气分档（温和提醒/正式催告）。
- 发送：SMTP 配置（设置页，凭据本地存储）；**发送前必须人工确认**；发送记录落库（收件人/主题/正文/时间/关联订单）。
- 失败重试与错误提示；发送失败的邮件可再次编辑发送。

### F7 设置

- SMTP 配置（主机/端口/账号/授权码/发件人显示名，连接测试按钮）。
- 提醒规则配置（N 天阈值、扫描间隔、停滞天数）。

## 5. AI 行为边界（开发与测试依据）

| 边界 | 规则 |
| ---- | ---- |
| 能做 | 从上传文档抽取订单字段（附置信度）；生成邮件草稿（可编辑可弃用）；将订单已有字段填充进单证模板 |
| 绝不做 | 自由生成/修改金额、数量、单价、日期、币种、HS 编码等关键字段（单证数字只能来自订单确认数据）；未经人工确认直接发送邮件；未经确认将解析结果写入订单库；对图片型 PDF 假装解析成功 |
| 不确定时 | 字段置信度 <0.7 → 标黄标注并要求人工处理；解析整体失败 → 转手动录入；邮件涉及索赔/法务/争议 → 草稿中标注「建议人工处理，AI 草稿仅供参考」并保守措辞 |

## 6. 效果指标定义

- 订单录入时长（上传→确认入库）、解析字段命中率（抽取字段与人工最终值一致比例，目标 ≥90%）
- 单证生成时长、校验器拦截次数（质量观测）
- 邮件采纳率 / 修改率 / 发送成功率
- 异常看板提醒覆盖率（规则命中订单 100% 出现）与逾期订单占比变化
