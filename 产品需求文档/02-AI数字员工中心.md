## 1. 模块定位

### 1.1 页面目标

展示企业当前拥有的 AI 员工，并查看其：

- 当前状态
- 今日工作量
- KPI
- 当前任务

### 1.2 AI 员工角色清单（来自全局信息架构 §1）

| 角色             | 职责概述                       | 对应工作台文档                          |
| ---------------- | ------------------------------ | --------------------------------------- |
| 🤖 AI 获客员工   | 寻找潜在客户、评分、发现联系人 | [03-AI获客](./03-AI获客.md)             |
| 🔍 AI 客户研究员 | 客户分析、画像与洞察           | [04-客户360°](./04-客户360°.md)         |
| 💼 AI 外贸销售员 | 询盘回复、报价沟通、协助成交   | [06-AI销售工作台](./06-AI销售工作台.md) |
| 📧 AI 跟进员工   | 自动跟进策略执行               | [07-AI自动跟进](./07-AI自动跟进.md)     |
| 👔 AI 外贸经理   | 经营分析、风险预警             | [13-AI外贸经理](./13-AI外贸经理.md)     |
| （跟单员工）     | 订单协同与风险跟踪             | [10-订单中心](./10-订单中心.md)         |

> **MVP 承载决策（v0.2）**：6 个员工卡片全部展示。AI 获客 / 销售 / 跟进 / 经理跳转各自独立工作台；AI 客户研究员跳转[客户 360°](./04-客户360°.md)（04）的 AI 洞察区（04 为 P0，可承载）；AI 跟单员工因订单中心（10）为 P1，其卡片显示「即将上线」占位、入口禁用，随 P1 一起启用。**占位状态（v0.3 决策）**：状态用 `idle`（⚪）+ `statusDetail=「即将上线，随订单中心（P1）启用」`，不新增 `employee_status` 枚举值。

## 3. 功能需求

| 编号  | 需求            | 说明                                                                                                                                                                                              |
| ----- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-01 | AI 员工卡片列表 | 每个员工展示：角色图标与名称、实时状态（全局语义色 🟢🟡🔵🔴⚪）、今日工作量（如「今日找到 28 个客户」）、KPI 完成进度条                                                                           |
| FR-02 | 进入工作台      | 每张卡片提供「进入工作台 →」入口，按 §1.2 承载决策跳转；暂无工作台的角色显示「即将上线」且入口禁用                                                                                                |
| FR-03 | 创建 AI 员工    | 页面右上角「+ 创建 AI 员工」入口，采用**分步向导**（见 §3.1），按 §26 核心能力模型配置：Role / Goal / SOP / Skills / Tools / Knowledge / Memory / Tasks / Workflow / Permissions / Approval / KPI |
| FR-04 | 查看当前任务    | 卡片支持查看该员工当前执行的任务（联动 AI 任务中心）                                                                                                                                              |

### 3.1 创建 AI 员工分步向导（v0.2 决策）

按 §26 能力模型拆为 4 步；选定角色后由该角色预置模板（`GET /api/v1/ai-employees/roles`）预填后续字段，用户按需调整，逐步校验通过方可进入下一步。

| 步骤         | 内容                                                    | 字段（对应[接口文档 02 §1.2](./页面级字段与接口文档/02-AI数字员工中心.md)） |
| ------------ | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| ① 选择角色   | 角色卡片单选，选中即加载该角色预置 SOP / Skills / Tools | role                                                                        |
| ② 目标与 SOP | 员工命名、Goal 描述、SOP 模板绑定与调整                 | name / goal / sopTemplateId                                                 |
| ③ 能力配置   | 技能、工具、知识范围、记忆、工作流绑定                  | skills / tools / knowledgeScope / memoryConfig / workflowId                 |
| ④ 权限与 KPI | 权限白名单、审批策略、KPI 目标（口径见 §3.2）           | permissions / approvalPolicy / kpiConfig                                    |

- ④ 提交后调用 `POST /api/v1/ai-employees` 创建；6 类高风险动作审批绑定红线在向导内即时校验（配置 `none` 返回 `42201`）。
- 创建/修改员工为高权限操作：`role ∈ {admin, manager}`。
- **SOP 编辑边界（v0.3 决策）**：第 ② 步仅支持「选择预置模板 + 高级设置参数级微调」（如 `match_product` 阈值，见 LangGraph 工作流 00）。`sop_template.content` 为结构化 jsonb（节点/边/审批标记，编译为 LangGraph 图，见总纲 §4.3），MVP 不开放结构/富文本编辑；SOP 可视化编排放 P1+。

### 3.2 KPI 口径定义（v0.2 决策）

MVP 每角色固定 **1 个日指标**（`period=daily`）；达成值按「任务产出 + 业务表」实时聚合（见 [ER 02 §4](./PostgreSQL 数据库 ER 图/02-AI员工与任务模块.md)，不落列），目标值 target 由企业自填：

> **KPI 建议目标值（v0.3 决策）**：建议值挂角色模板预填（`GET /api/v1/ai-employees/roles` 返回 preset 含 `kpiConfig` 建议），向导第 ④ 步可改。初始建议：获客 35/日、研究员 20/日、销售 30/日、跟进 50/日、经理 1 份报告/日（跟单员工 P1 定）；均为初始值，待运营数据校准。

| 角色                | metric 枚举       | 指标含义                        | 聚合来源                         |
| ------------------- | ----------------- | ------------------------------- | -------------------------------- |
| lead_hunter         | `daily_leads`     | 今日新发现客户数                | leads                            |
| customer_researcher | `daily_profiles`  | 今日完成分析/画像客户数         | leads 分析产出                   |
| sales               | `daily_replies`   | 今日处理询盘/回复数             | messages                         |
| follow_up           | `daily_followups` | 今日自动跟进执行数              | follow_up 任务 / messages        |
| merchandiser        | `active_orders`   | 在跟订单数（P1 随订单中心启用） | orders                           |
| manager             | `daily_reports`   | 今日生成经营分析/报告数         | ai_task（business_analysis）产出 |

## 4. AI 行为边界

- 本页为**管理视图**：只展示与查看，不承载业务执行。
- 创建 AI 员工属于高权限操作，受权限管理约束（见 16-系统设置）。
