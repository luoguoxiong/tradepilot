## 1. 背景与目标

外贸业务员每天通过 Google、B2B 平台和社媒开发海外客户，单客户开发流程（搜索→判断匹配→人工分析官网→写开发信）约 20 分钟。本产品用 AI 将该流程压缩到 **3~5 分钟/客户**。

## 2. 目标用户与场景卡

| 项       | 内容                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------- |
| 用户画像 | 外贸一线业务员 / SOHO；每天开发 5~20 个新客户；工具 = Google + B2B 平台 + 社媒 + Excel             |
| JTBD     | 「当我要开发一个新客户时，我想快速知道这家公司值不值得做、怎么打动他，以便把时间花在高意向客户上」 |
| 环境     | Web 浏览器；可能同时处理一批候选公司；有 LLM API（OpenAI/DeepSeek 兼容）                           |

## 3. 核心用户流程（人机协同）

```text
① 配置我的产品档案（产品关键词/说明 + 目标市场，一次配置多次复用）
        ↓
② AI 自动搜索潜在客户（按产品关键词+目标市场调用搜索引擎，生成线索队列）
   （备用通道：粘贴公司名/官网URL批量导入）
        ↓
③ AI 批量抓取客户官网 → 生成客户分析报告（公司信息/主营业务/匹配度证据链）
        ↓
④ 评分与排序（A/B/C/D 评级，可解释评分），业务员浏览筛选
        ↓
⑤ 业务员确认值得开发的客户
        ↓
⑥ AI 依据分析报告生成个性化开发信（英文默认，可编辑）
        ↓
⑦ 一键复制/导出，业务员自行发送（v1 不做自动发送）
```

人机协同点：⑤ 人工确认客户、⑦ 人工编辑+发送。AI 负责 ②③④⑥。

## 4. 功能需求

### F1 产品档案（My Product Profile）

- 输入：产品名称与说明、产品关键词、目标国家/市场、我的差异化优势（工厂/认证/案例，可选）。
- 支持多档案切换（如按产品线）。档案用于所有分析、评分、开发信生成。

### F2 线索获取：自动搜索（v1 主通道）+ 粘贴导入（备用）

- **自动搜索（主通道）**：基于产品档案的关键词+目标市场，自动生成搜索 query 组合（如 `"{keyword}" wholesale {country}`、`"{keyword}" importer/distributor {country}`），调用搜索引擎 API 获取候选公司。
  - 搜索引擎适配器（可配置）：默认 **DuckDuckGo**（免费无需 key，开箱即用）；可选配置 **Google Custom Search** 或 **SerpAPI**（结果更稳定，需用户自备 key）。
  - 从搜索结果中提取公司名+官网域名，去重（域名级）、过滤（排除亚马逊等电商平台/目录站/新闻页）后生成线索队列。
  - 业务员可勾选全部或部分线索进入批量分析。
- **粘贴导入（备用）**：输入公司名或官网 URL，一行一条，批量提交；同样去重。
- 同一域名已有分析结果不重复分析（缓存复用）。

### F3 官网抓取与客户分析报告

- 抓取目标官网首页 + 关键子页（About/Products/Contact，自动发现，上限 5 页）。
- 生成分析报告，字段：
  - 公司概况：公司名、网站、主营业务（来自官网原文）
  - 产品线与业务范围（原文摘要+出处）
  - 市场覆盖/客户类型（官网可见证据）
  - 规模与资质线索（成立时间/认证/员工规模——仅官网可见时填写）
  - 联系方式：邮箱/联系人/表单（规则抽取）
  - 与我方产品匹配度评估（AI，含证据）
- **数据来源标注**：每个事实字段附来源 URL；抓取失败/信息缺失如实标注「未获取到」。

### F4 评分与评级（可解释）

- 维度与权重（规则+AI 混合）：

| 维度            | 权重 | 方式                            |
| --------------- | ---- | ------------------------------- |
| 产品匹配度      | 40%  | AI 评估：高/中/低 + 证据        |
| 进口商/采购证据 | 25%  | AI 评估：强/弱/无 + 证据        |
| 规模与资质      | 15%  | 证据缺失计 0，不推测            |
| 联系可得性      | 10%  | 规则：有邮箱=10，仅表单=5，无=0 |
| 市场匹配        | 10%  | AI 评估：高/中/低 + 证据        |

- 输出 0-100 分 + A（≥80）/B（60~79）/C（40~59）/D（<40）评级；每个维度显示得分依据。
- 线索列表按得分排序，支持筛选与批量确认。

### F5 开发信生成

- 输入：客户分析报告 + 产品档案。
- 结构：个性化钩子（引用客户官网证据）→ 展示我方匹配点 → 提问钩子 → 单一 CTA。
- 约束：正文 <150 词；默认英文，可选语种；每次生成 2 个标题候选 + 1 个正文；业务员可编辑。
- 生成后一键复制 / 导出 .txt/.eml。

### F6 任务队列与状态

- 批量导入后异步处理，每条线索状态：待处理/抓取中/分析中/已完成/失败。
- 失败可重试；重复点击不产生重复分析。

## 5. AI 行为边界（开发与测试的依据）

**能做什么**

- 基于抓取到的官网原文总结公司信息、主营业务、产品线，并标注来源。
- 依据产品档案评估匹配度，输出等级+证据。
- 依据分析报告中的已确认证据生成个性化开发信。

**绝不做什么**

- 绝不编造官网/搜索结果中不存在的公司事实（成立年份、规模、进口记录、客户案例）。
- 绝不在开发信中编造客户侧细节或虚构我方能力（认证/案例/价格承诺/MOQ）——我方卖点只能引用产品档案中用户自己填写的内容。
- 绝不猜测抓取失败客户的完整信息；缺失就标注缺失。
- 绝不自动发送任何邮件（v1）。

**不确定时怎么办**

- 官网证据不足 → 该字段标「未获取到」，评分对应维度记 0 并说明。
- 抓取失败 → 报告显示失败原因 + 降级为「仅搜索摘要（如有）」+ 提示人工补充粘贴官网内容。
- 匹配度无法判断 → 输出「无法评估」并列出缺失信息，不打分。

## 6. 效果指标与验收标准

| 指标       | 验收标准                                                                          |
| ---------- | --------------------------------------------------------------------------------- |
| 核心流程   | 粘贴 URL → 完成报告+评分 → 确认 → 生成开发信 → 复制导出，全程 ≤3 分钟（不含排队） |
| 事实准确率 | 抽样 20 个客户，报告中事实字段与官网原文一致率 ≥95%                               |
| 幻觉率     | 报告与开发信中「无出处事实」数量 = 0                                              |
| 评分解释性 | 每个客户的每个评分维度都有可见依据                                                |
| 开发信合规 | 正文 <150 词，无垃圾词，客户侧细节 100% 来源于报告                                |
| 抓取成功率 | ≥80%，失败走降级路径并提示                                                        |
| 批量能力   | 50 条线索批量导入可完成处理，失败可重试                                           |
| 自动搜索   | 一次搜索返回 ≥10 条有效线索（排除电商/目录站后），全程无需人工干预                |

## 7. 范围划分

- **v1（本轮）**：产品档案、**自动搜索找客户（DDG 默认 + Google CSE/SerpAPI 可选）**、粘贴导入备用通道、官网抓取+分析报告、评分评级、确认、开发信生成与导出、任务队列。
- **v2+**：多语种本地化增强、邮件发送集成（含频控/退订）、回复追踪、团队协作、CRM 导出、更多搜索源（海关数据/社媒）。

## 8. 非功能需求

- 抓取限速与超时控制（单页超时 ≤15s，礼貌抓取），结果缓存避免重复抓取同一域名。
- LLM 调用可配置（OpenAI/DeepSeek 兼容 base URL + key），多层级容错：超时重试→降级模型→明确报错。
- 分析报告与开发信生成历史可追溯（可重新查看/重新生成）。
- 仅抓取公开网页；不存储用户以外第三方隐私数据超出分析所需。
