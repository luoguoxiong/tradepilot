## 1. 页面区块与字段清单

|---|---|---|---|

### 1.2 给 AI 下任务（FR-01～03）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| goalText | string | ✓ | 自然语言目标，如「帮我寻找美国做跑鞋的品牌，希望他们可能需要 Carbon Fiber Insoles」 |
| optimizedGoal | string | — | 「✨ AI 自动优化目标」后的文本 |
| parsed | object | ✓ | AI 结构化解析结果（见 1.3） |

### 1.3 创建获客任务表单（FR-07～09）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| goalText | string | ✓ | 原始目标描述 |
| parsed.targetMarket | string | ✓ | 目标市场（国家/地区，如 `USA`） |
| parsed.customerType | string | ✓ | 客户类型（如 `Shoe Brand`） |
| parsed.targetProduct | string | ✓ | 目标产品（如 `Carbon Insoles`） |
| parsed.companySize | string | — | 公司规模区间（如 `50-500+`） |
| advancedSettings | object | — | 高级设置（待澄清字段：年进口额、职衔过滤等），透传给执行引擎 |
| targetCount | number | — | 目标发现数量（进度分母，如 35） |

### 1.4 当前任务进度卡（FR-04）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| taskId | string | ✓ | 任务 ID |
| goal | string | ✓ | 任务目标摘要 |
| progressPct | number | ✓ | 总进度百分比 |
| foundCount / targetCount | number | ✓ | 已发现 / 目标数（如 28/35） |
| currentStep | string | ✓ | 当前步骤文案（如「分析公司官网」） |
| status | string | ✓ | taskStatus 枚举 |

### 1.5 AI 实时工作日志（FR-05）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| logId | string | ✓ | 日志 ID |
| time | string | ✓ | 发生时间 |
| type | string | ✓ | `search` 🔍 搜索 / `found` ✓ 发现公司 / `crawl` 🌐 读取官网 / `match` 🧠 产品匹配 / `contact` 👤 发现联系人 / `lookup` 📩 查找联系方式 / `error` |
| content | string | ✓ | 文案（含匹配度等动态值） |
| leadId | string | — | 关联发现的客户（可点击） |

### 1.6 客户发现列表（FR-10～14）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| leadId | string | ✓ | 发现客户 ID |
| companyName | string | ✓ | 公司名 |
| country | string | ✓ | 国家（国旗展示） |
| industry | string | — | 行业 |
| matchPct | number | ✓ | 产品匹配度（进度条） |
| scoreLevel | string | ✓ | leadValue：`high` / `medium` / `low` |
| inCrm | boolean | ✓ | 是否已加入 CRM（已加入的置灰/过滤） |
| matchReasons | object[] | — | 匹配理由（Insight Schema，见 00 §4.1），Tooltip 展示 |

筛选与 Tab：`valueLevel`（全部/高/中/低，各档数量）、`keyword`、`country`、`industry`、`minMatchPct`。

## 3. 接口详细定义

### 3.1 POST /api/v1/lead-tasks/parse

请求：`{ goalText: "帮我找美国做跑鞋的品牌，可能需要碳纤维鞋垫" }`

响应 `data`（解析结果可编辑后回传创建）：

```json
{
  "parsed": { "targetMarket": "USA", "customerType": "Shoe Brand",
              "targetProduct": "Carbon Fiber Insoles", "companySize": "50-500+" },
  "optimizedGoal": "寻找美国主营跑鞋的中大型品牌，匹配碳纤维鞋垫产品线",
  "confidence": 0.9, "reasons": [{ "text": "识别到国家+行业+产品三要素" }]
}
```

### 3.2 POST /api/v1/lead-tasks

请求：

```json
{ "goalText": "帮我寻找美国做跑鞋的品牌…", "parsed": { "targetMarket": "USA", "customerType": "Shoe Brand", "targetProduct": "Carbon Fiber Insoles", "companySize": "50-500+" },
  "advancedSettings": {}, "targetCount": 35, "employeeId": "emp_1" }
```

响应：`{ taskId, status: "running" }`；随后进度/日志/暂停复用任务接口：

- `GET /tasks/{taskId}`（进度卡 1.4）
- `GET /tasks/{taskId}/logs?after={logId}&limit=50`
- `POST /tasks/{taskId}/pause`、`POST /tasks/{taskId}/resume`、`POST /tasks/{taskId}/cancel`

### 3.3 GET /api/v1/leads

请求参数：`valueLevel(high|medium|low|all)`、`keyword`、`country`、`industry`、`minMatchPct`、`taskId`、`inCrm(boolean)`、分页。

响应 `data.items[]`：1.6 列表字段。示例：

```json
{ "leadId": "lead_1", "companyName": "ABC Sports", "country": "US", "industry": "Sports",
  "matchPct": 92, "scoreLevel": "high", "inCrm": false,
  "matchReasons": { "value": 92, "confidence": 0.92, "reasons": [
      { "text": "产品高度匹配", "evidence": "官网在售 Running Shoes 产品线", "source": "web_crawl" } ] } }
```

### 3.4 POST /api/v1/leads/add-to-crm

请求：`{ leadIds: ["lead_1", "lead_2"] }`

响应：`{ created: 2, duplicated: 0, customers: [{ customerId, leadId }] }`；重复判定（同域名/同公司名）按去重规则返回 `duplicated` 计数（去重口径待澄清，见需求文档 §7.3）。

### 3.5 POST /api/v1/leads/batch-analyze

请求：`{ leadIds: [...] }` → 响应 `{ taskId }`（异步，产出 AI 洞察写入客户 360°）。

## 4. 联动与边界

- **评分可解释**：`matchPct / scoreLevel` 必须带 `matchReasons`（Insight Schema），纯数字不给（需求文档 §4）。
- **联系方式合规**：联系人发现仅限公开商务渠道，接口不做隐私数据抓取；合规开关在 16-系统设置。
- **加入 CRM 是写操作**：受数据权限约束；AI 不自动触发对外触达。
- 知识依赖：产品匹配调用 [11-知识中心](./11-知识中心.md) 检索接口（`scene=lead_match`）。
- 高风控行为（如批量营销式触达）生成 `appr_` 审批项（[12-AI审核中心](./12-AI审核中心.md)）。
