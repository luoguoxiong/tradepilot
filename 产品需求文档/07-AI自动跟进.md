## 1. 模块定位

### 1.1 页面目标

按时间线策略对客户执行自动化跟进（SOP），减少人工遗忘与跟进中断；高风险跟进动作（如发送）接受人工审核。

## 3. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-01 | 跟进任务总览 | 展示「正在执行：N 个跟进任务」；Tab：全部 / 今天待执行 / 等待审核 / 已完成 |
| FR-02 | 跟进任务列表 | 字段：客户、当前阶段（Follow-up #N / Quote Follow-up）、下次跟进时间、状态（🟢 Ready / 🟢 Scheduled / 🟡 Approval） |
| FR-03 | 跟进策略时间线 | 默认策略：Day 0 Initial Email → Day 3 Product Value → Day 7 Product Case → Day 14 Customer Case → Day 30 Break-up Email；节点状态：已完成 ✓ / 执行中 ⏳ / 未开始 ○ |
| FR-04 | 新建 / 编辑策略 | 「+ 新建策略」「编辑策略」，可自定义跟进节奏与内容；多套策略并存（适用范围 `target_scope`：客户价值 / 行业 / 标签），默认策略不可删、可复制后编辑（见 §7） |
| FR-05 | 执行记录 | 「查看执行记录」查看每次跟进的执行明细与结果 |
| FR-06 | 审核联动 | 状态为 🟡 Approval 的跟进任务进入 AI 审核中心，人工批准后发送 |
| FR-07 | 应用到客户 | 策略详情「应用到客户」：单选 / 批量多选（接口 `apply`）；客户无进行中任务才创建，每客户同时仅 1 个进行中任务（见 §7） |

## 4. AI 行为边界

- **发送类动作受控**：跟进邮件默认经「等待审核」或按策略自动执行，具体自动化程度由企业按客户价值分级配置（高价值客户建议强制人工审核）。
- Break-up Email（分手信）等敏感性内容必须人工审核。
- 客户中途回复后，**跟进策略应自动暂停/调整**，避免机器邮件与人工沟通撞车（待详细设计确认）。
- 跟进内容禁止编造优惠、交期、价格承诺。

## 6. 效果指标（建议）

- 跟进执行率：按策略按时执行的任务比例。
- 审核通过率与编辑率：衡量 AI 跟进内容质量。
- 跟进回复率：跟进触达后客户回复的比例（>5% 为优秀参照）。
- Break-up 邮件后的客户唤醒率。

## 7. 待澄清问题

1. ~~策略模板体系：默认策略之外，是否支持按客户分级 / 行业配置多套策略。~~ → **已澄清**（v0.2）：
   - **多套策略**：已支持（`target_scope` 按客户价值 / 行业 / 标签圈定适用范围，`auto_send_policy` 分级管控，见 [ER 05](./PostgreSQL%20数据库%20ER%20图/05-销售邮件与自动跟进模块.md)）。
   - **挂载机制**：手动应用为主——策略详情「应用到客户」（单选 / 批量多选，接口 `apply`，FR-07）；客户无进行中任务才创建，**每客户同时仅 1 个进行中任务**；按 `target_scope` 自动匹配挂载为 **P1**。
   - **默认策略**：注册时种子化（`is_default`，Day 0/3/7/14/30），不可删除、可复制后编辑（前端复制提交新建）；不做行业模板市场（P1+）。
2. ~~「今天待执行」的触发时点与时区处理（客户当地时间 vs 企业当地时间）。~~ → **已澄清**（v0.2）：按**企业当地时间**触发（`org.timezone`）+ 组织级发送时间窗（`org.send_rules.sendWindow`，默认 09:00–18:00 可配，16 FR-12）；到期落在窗口外顺延至下一窗口起点；「今天待执行」= 企业当地日历日；`next_run_at` 统一存 UTC。客户当地时间触发依赖客户时区数据（MVP 无），列为 P1。
3. ~~跟进频控与反垃圾规则（同一客户最大触达频率）。~~ → **已澄清**（v0.2）：组织级规则（16 FR-12 / `org.send_rules`）：`minTouchIntervalDays` 默认 3——同一客户任意 outbound 邮件（含人工发送）最小间隔；**Scheduler 入队前预检**，不满足则顺延 `next_run_at` 并写执行记录 `skipped(frequency_capped)` 留痕；每客户进行中跟进任务唯一。
   - **顺延目标公式（v0.2.1 收口，Scheduler 频控预检与图内 `schedule_next` 共用）**：`候选 = max(当前 next_run_at, 该客户最近一次 outbound 时间 L + minTouchIntervalDays 天)`；再按 `org.timezone` 做**窗口对齐**——当地时刻 < 09:00 → 当日窗口起点，≥ 18:00 → 次日窗口起点，窗口内保持（窗口取 `send_rules.sendWindow` 默认 09:00–18:00）。频控顺延后同样过窗口对齐，保证落点必在窗口内，Scheduler 到期即可直接入队；顺延后 `next_run_at` 前移不再被扫描，每次预检失败至多写一条 `skipped(frequency_capped)`。
