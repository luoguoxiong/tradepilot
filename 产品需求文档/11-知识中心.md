## 1. 模块定位

### 1.1 页面目标

企业知识的统一上传、分类、索引与检索（RAG 底座），为所有 AI 员工提供有据可依的知识来源：获客匹配、销售话术、报价依据、经营分析都从这里取数。

## 3. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-01 | 上传知识 | 「+ 上传知识」；支持 PDF / DOCX / MD 等格式 |
| FR-02 | 知识分类 | 全部 / 产品 / 公司 / 销售 / 客户 / FAQ（含流程知识等其他类别） |
| FR-03 | 知识搜索 | 关键词搜索知识文档 |
| FR-04 | 索引状态管理 | 每份文档显示索引状态：已索引 ✓ / 索引中 ⏳ / 失败（含重试） |
| FR-05 | 知识统计 | Documents 数量、Chunks 数量、最近更新时间 |
| FR-06 | 知识检索服务（RAG） | 对内提供检索 API：AI 销售 / 获客 / 报价 / 经理各场景按需召回，引用时标注来源文档 |

---

## 4. AI 行为边界

- **知识库是 AI 事实的唯一来源**：AI 引用知识时必须可追溯到具体文档；知识库无依据的问题，AI 应明确说「知识库中没有相关信息」，禁止编造。
- 索引失败要有明确提示与重试机制，不允许静默丢失知识。
- 知识删除 / 更新后，相关 AI 引用需同步失效（待详细设计确认缓存策略）。

## 6. 效果指标（建议）

- 索引成功率与平均索引时长。
- 知识检索命中率：AI 回复中的引用能命中正确文档的比例。
- 「知识库无依据」提示率（异常高说明知识缺口，需引导补充上传）。

## 7. 待澄清问题

1. 支持的文件格式与大小上限；网页 / 邮件附件是否可一键入库。
2. 知识的版本管理与更新策略（覆盖旧版 vs 多版本共存）。
3. 知识权限：是否按团队角色限制可见知识范围。
