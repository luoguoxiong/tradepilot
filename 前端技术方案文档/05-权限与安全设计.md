## 1. 基本原则

1. **前端权限只是 UX，服务端是唯一权威**：任何前端裁剪失效都不构成安全漏洞，越权一律由 `40301` 兜底；
2. 三角色模型（接口规范：`role = admin / manager / sales`）随 JWT 下发，前端不维护角色数据源；
3. 权限判断收敛到单点，禁止视图内散落 `role === 'admin'` 判断。

## 2. 数据范围（Data Scope）

接口规范 §4.4：资源带 `ownerId`；业务员默认仅本人资源，经理/管理员可见团队/全部；列表接口 `scope=self|team|all`。

| 角色默认上限 | scope UI |
|---|---|
| sales | 固定 `self`，`ScopeSelect` 不渲染 |
| manager | 默认 `team`，可选 self/team |
| admin | 默认 `all`，可选 self/team/all |

- scope 值入 URL query（列表状态可分享）；越权访问详情（直接输入他人资源 URL）→ `40301` 渲染无权限空态，不重定向；
- CRM 批量改派：仅 manager/admin 可见「改派」操作（owner 变更权限约束：业务员不可私改 ownerId）。

## 3. 前端权限实现

### 3.1 三层裁剪

```text
路由级：meta.roles → 守卫拦截（[02 §3](./02-路由与页面架构.md)）
页面级：v-permission 指令 → 元素级显隐/禁用
逻辑级：usePermission() → 组合式判断（复杂场景，如「编辑后批准」按钮可用性）
```

```ts
// directives/v-permission.ts
// v-permission="['admin','manager']"  → 无权限移除元素
// v-permission.disabled="['admin']"   → 保留元素但禁用（配合 Tooltip 说明）
```

### 3.2 操作-角色映射基线

| 操作 | 可见角色 | 依据 |
|---|---|---|
| AI 员工创建/编辑 | admin / manager | 02 v0.3 权限约束 |
| 员工账号/角色管理、审批规则 | admin / manager | 16 权限模型 |
| 知识文档删除/重试索引 | admin / manager | 11 §（知识为组织共享，删除限管理） |
| 审批处置 | admin / manager | 12（审批仅限管理角色） |
| CRM 批量改派 / ownerId 变更 | admin / manager | 工程约定（业务员不可转 owner） |
| 客户/会话/任务日常操作 | 全角色（按 scope） | — |

> 该表为前端裁剪基线，与接口约束不一致时以接口/后端方案为准并回改本表。

## 4. 前端安全

### 4.1 XSS（本项目首要风险源）

风险点：AI 生成内容、邮件正文（外部输入）、知识文档内容均经富文本渲染。

- 一律 **DOMPurify 消毒**后注入（白名单：基础标签 + `a[href]` 限制协议 `http/https/mailto`）；禁用 `v-html` 直插——ESLint 自定义规则禁止裸 `v-html`；
- 邮件原文预览采用沙箱 iframe（`sandbox` 无 allow-scripts）承载，隔离外部邮件脚本；
- CitationPopover/文件名等动态文本走插值渲染（自动转义）。

### 4.2 Token 与会话

- JWT 存 localStorage（同域部署 + CSP 收敛 XSS 面作为补偿控制）；请求层内存缓存，`40101` 统一清会话；
- 登出 / `40101` / 手动清数据时**全量清理**（token、缓存 store、vue-query cache）；
- `redirect` 参数仅允许站内相对路径（防开放重定向）。

### 4.3 其他

| 项 | 措施 |
|---|---|
| CSP | 部署层下发（[01 §5.3](./01-工程架构与规范.md)）：`default-src 'self'`、脚本禁 inline（hash 白名单）、`object-src none` |
| 点击劫持 | `X-Frame-Options: DENY` + `frame-ancestors 'none'` |
| 敏感展示 | 邮箱凭据脱敏（后端返回已脱敏，前端不做明文缓存）；成本字段（cost_snapshot）仅报价/订单详情按角色渲染，AI 展示层不出现成本（知识生成已排除 cost_price 口径对齐） |
| 依赖安全 | pnpm audit + Renovate/Dependabot 周期升级；lockfile 提交 |
| 上传 | 前端限制扩展名与大小（与接口约束一致），MIME 校验以服务端为准 |

## 5. 错误监控与可观测

- **Sentry**（@sentry/vue）：路由切换/组件异常/Vue warn 采集；`traceId`（响应头/响应体）作为 tag 注入，与后端日志贯通排查；
- release 关联 `VITE_RELEASE`（git sha）+ sourcemap 上传（staging）；
- Web Vitals（web-vitals 库）上报 LCP/INP/CLS，作为 [06 性能](./06-性能优化与测试策略.md)指标回归依据；
- 控制台日志：仅 dev 环境输出；生产禁用（防信息泄漏）。
