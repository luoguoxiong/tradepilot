## 1. 状态分类矩阵

| 状态类别 | 归属 | 实例 |
|---|---|---|
| 服务端状态 | TanStack Query | 列表、详情、聚合、审批队列、任务日志 |
| 客户端全局 | Pinia | 会话（auth）、偏好（app）、枚举映射（dict）、通知（notify） |
| URL 状态 | Vue Router query | 页签、筛选、分页（可分享/回退） |
| 组件本地 | ref/local | 抽屉开合、表单草稿（未提交态） |

> 判定规则：凡是「后端为事实源」的数据一律 Query，禁止拷贝进 Pinia 双写。

## 2. Pinia Stores

| Store | 职责 | 关键状态 |
|---|---|---|
| `authStore` | 会话 | `token`、`user { userId, orgId, role, name }`、`onboarding.currentStep`、`org { timezone, defaultCurrency, defaultLanguage, sendRules }` |
| `appStore` | 布局偏好 | sider 折叠、locale、菜单状态 |
| `dictStore` | 全局枚举 | [接口规范 §3](../产品需求文档/页面级字段与接口文档/00-总览与接口规范.md) 全部枚举 → `{ label(i18n key), color token }` 映射表 |
| `notifyStore` | 通知 | 待审数量、轮询开关、未读计数 |

## 3. 请求层（axios）

```text
api/http.ts
├── 请求拦截：注入 Authorization: Bearer <token>；Accept-Language；
│            携带 requestId（用于 trace 排查）
├── 响应拦截：code === 0 → 解包返回 data；非 0 → 统一错误管道（§4）
└── 通用配置：baseURL = VITE_API_BASE；timeout 15s（上传 60s）
```

- 接口资源按模块拆分 `api/resources/*.ts`，函数签名强类型：

```ts
// api/resources/customers.ts
export const getCustomers = (params: CustomerListReq) =>
  http.get<PageResp<CustomerItem>>('/customers', { params })
```

- 租户隔离不传 `orgId`（服务端从 JWT 解出，接口规范 §2.1）；
- 幂等：写操作默认携带 `Idempotency-Key`（uuid，同一次表单提交复用），防重复提交（对应 `40901` 场景兜底）。

## 4. 错误处理管道

统一响应 `{ code, message, data, traceId }`（接口规范 §2.2）。错误码 → 前端行为映射：

| code | 行为 |
|---|---|
| `40001` 参数错误 | 表单内联标红（若能映射到字段）否则 message 提示 |
| `40101` 未认证 | 清会话 → `/login?redirect=...`，只触发一次 |
| `40301` 无权限 | message 提示「无权限」；列表查询场景渲染空态 |
| `40401` 资源不存在 | 页面级 404 空态（详情页）/ 列表刷新该项 |
| `40901` 状态冲突 | 提示具体 message；乐观更新的操作**回滚**并 refetch |
| `42201` 业务校验失败 | 业务提示（如报价低于利润红线），中断提交流程，保留表单 |
| `42901` 频率限制 | toast 提示 + 按钮进入冷却（读取 Retry-After） |
| `50001` 服务内部错误 | 全局 toast + traceId 展示（便于客服排查） |
| `50301` 依赖不可用 | 页面内降级提示条（LLM/邮箱不可用），不阻塞页面其余区块 |

实现：`http.ts` 抛出 `ApiError`；Query 层 `onError` 统一走 `notifyStore`；表单场景由调用方捕获做字段映射。

## 5. vue-query 约定

### 5.1 Query Key 规范

```ts
// query/keys.ts —— 层级化 key，保证失效精准
qk.customers.list(filters)          // ['customers','list',filters]
qk.customers.detail(id)             // ['customers','detail',id]
qk.customerInsight(id)              // ['customer-insight',id]
qk.tasks.logs(taskId, after)        // ['tasks',taskId,'logs',after]
```

### 5.2 缓存与刷新策略

| 数据 | staleTime | 说明 |
|---|---|---|
| Dashboard 聚合 | 30s | 手动刷新按钮触发 invalidate |
| 列表页 | 10s | 筛选变更即新 key，缓存保留可回退 |
| 详情页 | 30s | 窗口聚焦 refetch |
| 审批队列/待审数 | 15s | 高时效；处置动作后 invalidate |
| 任务详情（running） | `refetchInterval: 3s`（非 SSE 场景兜底） | 终态停止 |
| 字典/枚举/员工列表 | 10min | 变更点显式 invalidate |

### 5.3 乐观更新

仅用于**低风险高频**操作：审批处置（approve/reject 后列表即时移除该项）、CRM 批量改派、任务取消。流程：snapshot → mutate cache → onError 回滚 + refetch（配合 `40901`）。

> 报价/订单/发送类写操作**不做乐观更新**——本身要过审批或返回审批单号（`approvalRequired: true + approvalId`），成功后统一 invalidate 对应列表。

### 5.4 异步任务模式对齐

AI 长耗时操作遵循接口规范 §4.3：触发接口返回 `taskId` → 详情/日志/流接口获取进度。前端封装 `useTask(taskId)`：合并 `GET /tasks/{id}`（轮询）与 SSE 流（§6），输出统一 `{ status, progressPct, currentStep, logs, outputs }`。

## 6. SSE 实时数据流（P0 核心依赖）

### 6.1 接口事实

[14-AI任务中心 §3.4](../产品需求文档/页面级字段与接口文档/14-AI任务中心.md)：`GET /api/v1/tasks/{id}/stream`（SSE），事件四类：

```text
event: log      data: { logId, type, content }
event: progress data: { progressPct, currentStep }
event: status   data: { status, linkedApprovalId? }
event: done     data: { status, outputs }
```

### 6.2 `useTaskStream(taskId)` 封装

```ts
// sse/useTaskStream.ts 关键语义
- 用 fetch-event-source（原生 EventSource 无法带 Bearer 头）
- onmessage 按 event 类型归并进响应式 state：
    log      → 追加 logs[]（去重：按 logId；组件层虚拟滚动渲染）
    progress → 更新 progressPct / currentStep
    status   → 更新 status；waiting_approval 时提示并联动跳审批
    done     → 终态；主动 close()；invalidate 任务相关 query
- 断线重连：指数退避 1s→2s→4s（上限 30s），最多 5 次
- 降级：重连耗尽 → 切换轮询 GET /tasks/{id}/logs?after=<lastLogId>
  （增量拉取，hasMore 翻页），UI 无感
- 生命周期：组件卸载 / 路由离开 AbortController.abort()；
  页面隐藏（document.hidden）暂停，恢复可见时重连 + 补拉增量日志
- 幂等续传：建立连接前先拉一次 /logs?after=0 建立基线，
  SSE log 按 logId > lastLogId 过滤，避免重连窗口丢日志/重复
```

### 6.3 使用落点

| 页面 | 消费方式 |
|---|---|
| 03 获客工作台任务卡 | 进度条 + 实时日志流（自动滚动跟随、可暂停） |
| 任务详情抽屉（02/14 卡片入口） | 同上，终态展示 outputs |
| 06/07 任务态变化 | `status: waiting_approval` → 全局通知 + 审批中心角标刷新 |

## 7. 全局格式化约定

| 领域 | 约定 |
|---|---|
| 时间 | `dayjs.utc(x).tz(org.timezone)`；「今日待执行」按企业当地日历日分组；相对时间（3 分钟前）用于会话/日志 |
| 金额 | `formatMoney('12500.00','USD')` → `$12,500.00`；币种缺省 USD |
| 评分/置信度 | `confidence` 显示为百分比 + InsightCard 视觉分级（见 [04 §2](./04-核心交互与组件设计.md)） |
| ID | 内部 ID 不直接展示；有展示编号字段（quoteNo/orderNo/SKU）优先展示（接口规范 §2.4） |
| 文案 | i18n key 全覆盖；AI 产出原文渲染不翻译 |
