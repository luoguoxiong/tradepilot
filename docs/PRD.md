# TradePilot AI — 产品需求文档（PRD）

> 版本：v1.0（MVP）｜状态：待用户确认｜来源：`plan.md` 全量需求固化
> 本文档是后续阶段 2–9 的需求基线。任何范围变更须先更新本文档。

## 1. 产品概述

### 1.1 定位

**TradePilot AI** 是面向中国外贸 SOHO、外贸业务员、贸易商和中小型出口企业的 AI 海外客户开发平台（SaaS MVP）。

核心价值：帮助外贸业务员自动寻找海外潜在采购商，分析客户是否匹配，挖掘采购联系人，生成个性化英文开发信，并通过 CRM 管理客户跟进。

### 1.2 首期目标市场与方向

- 目标市场：美国、加拿大
- 产品方向：电子产品、电子配件、消费类电子产品
- 客户类型：海外进口商（Importer）、产品分销商（Distributor）、批发商（Wholesaler）、零售渠道商（Retailer）

### 1.3 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 外贸业务员 / SOHO（主角色） | 手动 Google 搜索客户、写开发信的业务人员 | 自动找客户、省时间、开发信质量高 |
| 贸易商 / 中小出口企业 | 有少量业务团队 | 团队可共用的轻量 CRM、客户跟进不遗漏 |

MVP 为单用户演示形态，多租户仅做数据层预留（tenant_id 列），不实现租户隔离逻辑。

## 2. 核心业务闭环（唯一 P0 主线）

```
输入产品（碳纤维鞋垫等）
        │
        ▼
[企业智能搜索] Google 搜索海外企业（Adapter：Real/Mock）
        │  清洗、去重（域名唯一）
        ▼
[采购联系人挖掘] Apollo 获取 Purchasing/CEO 等联系人（Adapter）
        │
        ▼
[海关数据验证] 查询真实进口记录，区分真实采购商与展示型网站（Adapter，Mock 须标注 DEMO）
        │
        ▼
[AI 客户匹配度分析] LLM 结构化输出 0–100 评分 + 5 项解释性分析（A/B/C/D 分级）
        │
        ▼
[AI 英文开发信生成] Subject + Body + Follow-up 1/2（仅草稿，不自动发送）
        │
        ▼
[CRM 客户管理] 保存客户、状态流转、跟进记录、下次跟进时间
```

范围铁律：闭环之外的任何功能一律 P1/P2，防止范围蔓延。

## 3. 功能模块与验收标准

### 3.1 企业智能搜索（CompanySearchTool）

**输入**：产品关键词、目标国家、企业类型、行业关键词、搜索数量。
**展示字段**：企业名称、官网、国家、简介、主营产品、企业邮箱（可合法获取时）、LinkedIn、来源、搜索时间。
**能力**：分页、结果去重（域名唯一）、收藏、批量导入 CRM。

验收标准：
- [ ] 按条件创建搜索任务，异步执行，前端可实时查看任务进度
- [ ] 结果列表字段齐全、分页可用、重复域名企业不重复出现
- [ ] 可收藏企业、可批量导入 CRM
- [ ] Mock 数据带 `source: 'demo'` 标记，前端显示 DEMO 徽章

### 3.2 采购联系人挖掘（ContactDiscoveryTool）

**目标职位**：Purchasing/Procurement/Sourcing/Import Manager、CEO、Founder。
**展示字段**：姓名、职位、所属企业、工作邮箱、LinkedIn、国家、来源、邮箱验证状态。
**约束**：一个企业多联系人、按 (company_id, email) 去重、支持 API 失败后手动补充、**不允许伪造联系人或邮箱**。

验收标准：
- [ ] Company Detail 可发起联系人挖掘并展示结果
- [ ] 无真实 API Key 时使用明确标注 DEMO 的演示数据
- [ ] 支持手动添加/补充联系人
- [ ] 重复邮箱联系人不重复入库

### 3.3 海关数据验证（CustomsDataTool）

**分析维度**：是否存在进口记录、进口国家、产品描述、HS Code、采购时间、频率、数量、供应商国家/信息。
**目标**：区分真实采购商与普通贸易/展示网站。

验收标准：
- [ ] Company Detail 可查询并展示海关采购记录（按维度结构化）
- [ ] 无 API Key 时提供明确标注 DEMO 的模拟数据，绝不伪装成真实记录
- [ ] 采购记录作为 AI 评分输入，且"采购记录可信度"占 25% 权重

### 3.4 AI 客户匹配度分析（LeadScoringTool）

**输入**：我方产品信息、企业基本信息与主营业务、采购记录、联系人职位、所在国家。
**输出**（六项缺一不可，禁止只给分数）：
1. 推荐评分（0–100，权重：产品匹配 30% / 业务匹配 25% / 采购记录可信度 25% / 联系人职位匹配 10% / 地区匹配 10%）
2. 客户匹配原因
3. 潜在采购需求
4. 可能的合作机会
5. 客户开发建议
6. 数据缺失和不确定性说明

**分级**：A 80–100（高优先级）/ B 60–79（值得开发）/ C 40–59（待观察）/ D 0–39（低匹配）。

验收标准：
- [ ] 同一企业连续两次评分，分数波动 ≤ 10 且等级一致（稳定性）
- [ ] 输出经结构化 JSON（zod）校验；非法输出重试一次后降级为结构化错误，接口不 500
- [ ] 采购记录缺失时照常评分，但不确定性说明必须注明数据缺失
- [ ] 评分与等级落库，Company Detail / Companies 列表可见

### 3.5 AI 英文开发信生成（EmailGenerationTool）

**输入**：我方公司介绍与产品信息、客户企业信息、联系人姓名职位、采购记录、AI 分析结果。
**输出**：Email Subject、Email Body、Follow-up Email 1、Follow-up Email 2。
**质量约束**：自然专业的商务英语、无 AI 套话、按客户业务定制、体现产品与采购需求的关联、**禁止编造客户采购记录**。

验收标准：
- [ ] 生成四件套并可在 Email Studio / Company Detail 预览
- [ ] 支持重新生成、编辑、复制、保存到 CRM
- [ ] 无采购记录的企业，生成邮件不含任何伪造采购内容
- [ ] MVP 阶段仅生成草稿，无任何自动发送路径

### 3.6 CRM 客户管理

**状态机**：New → Qualified → Contacted → Replied → Negotiating → Won / Lost。

**功能**：客户列表、详情（整合企业信息+联系人+采购记录+AI 分析+邮件+跟进时间线）、联系人管理、跟进记录、下次跟进时间、状态管理、搜索筛选、Excel/CSV 导入导出。

验收标准：
- [ ] 七态状态流转可用，非法跳转被拒绝
- [ ] 跟进记录与下次跟进时间可添加；Dashboard 显示待跟进卡片
- [ ] CSV 导出再导入，数据无损往返
- [ ] 搜索、筛选、分页可用

### 3.7 Lead Discovery Agent（任务编排）

**工具**：CompanySearchTool、ContactDiscoveryTool、CustomsDataTool、CompanyEnrichmentTool、LeadScoringTool、EmailGenerationTool。
**编排流程**：接收需求 → 搜索企业 → 清洗去重 → 获取联系人 → 查海关记录 → AI 匹配分析 → 合格客户存 CRM → 生成开发信。
**要求**：异步任务、状态查询、失败重试、单步骤失败后恢复、每步执行日志、外部 API 超时与错误处理、频率限制与成本控制。

验收标准：
- [ ] 任务状态机：pending → searching → enriching → scoring → emailing → done/failed
- [ ] 每个步骤可独立重试；单步失败不丢失已完成步骤的结果
- [ ] 每步执行日志落库可查；LLM 调用记录 Token 用量/成本

MVP 采用模块化工具调用 + 单一任务编排器，**不做多 Agent 协作**（P2）。

## 5. 优先级边界

### P0（MVP 核心，阶段 5–7 必须交付）
- 用户登录（注册/JWT/密码哈希）
- 我方产品资料 CRUD
- 企业搜索（Mock Adapter 优先跑通，Real 可无缝替换）
- 企业信息展示（列表 + 详情）
- AI 客户匹配度分析
- 英文开发信生成（草稿）
- CRM 客户管理（列表/详情/状态/跟进）

### P1（阶段 7 内完成）
- Apollo 联系人挖掘（Mock/Real + 手动补充 + 邮箱验证状态）
- 海关数据查询（Mock 标注 DEMO）
- 异步任务管理完善（重试/恢复/日志）
- CSV 导入导出

### P2（MVP 明确不做，仅在架构上不阻碍）
- 自动邮件发送、邮件回复分析、自动跟进
- 多 Agent 协作
- 订阅付费系统

## 6. 非功能性需求（硬性规则）

1. **数据真实性**：Mock/演示数据必须显著标注 DEMO；伪造联系人、邮箱、海关记录伪装成真实数据 = 交付失败。
2. **Adapter 模式**：Google Search、Apollo、海关数据全部封装在适配器后，业务代码零第三方调用逻辑；每个适配器都有无 Key 可用的 Mock 实现。
3. **Key 管理**：API Key 绝不硬编码；部署级默认走环境变量，用户级经 Settings 页写入 integrations 表（AES-256-GCM 加密存储、API 响应脱敏只返回尾 4 位）。
4. **可运行优先**：每个阶段以可运行、可演示状态收尾，禁止一次性生成大批未验证代码。
5. **邮件仅草稿**：MVP 无自动发送。
6. **技术栈**：React 18 + TS + Vite + Tailwind + shadcn/ui + Zustand；Node.js + TS + NestJS/Fastify + PostgreSQL + Prisma/Drizzle + Redis + BullMQ；OpenAI 兼容 LLM + Tool Calling + 结构化 JSON + Prompt 模板管理。

## 7. 假设（ASSUMPTIONS）

1. Web 应用（非原生移动端），现代浏览器。
2. 认证用 JWT（非 session cookie）。
3. 第三方 API Key（Google/Apollo/海关）大概率不配置，Mock Adapter 是演示主路径。
4. LLM 走 OpenAI 兼容协议，**指定 DeepSeek（deepseek-chat）作为演示与默认模型**。
5. 多租户仅预留 tenant_id 列，不实现隔离逻辑。
6. 后端框架**选型 NestJS**（用户已确认）；ORM（Prisma vs Drizzle）在阶段 2 以 ADR 决定。
