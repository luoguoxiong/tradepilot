## 1. 模块定位

### 1.1 页面目标

用户用自然语言下达获客目标，AI 数字员工自主完成「找客户 → 分析客户 → 评分」的全流程，产出可进入 CRM 的潜在客户列表。

### 1.2 核心工作流（§5.1）

```text
用户输入目标
      ↓
AI 解析市场与客户画像
      ↓
制定搜索策略
      ↓
发现潜在公司
      ↓
官网分析
      ↓
产品匹配
      ↓
客户评分
      ↓
联系人发现
      ↓
进入 CRM
```

### 3.4 高级设置字段定义（v0.2 澄清 §7.1）

高级设置折叠面板承载 5 个字段，随 `advancedSettings` 透传并存入 `ai_task.input`；默认值来自员工绑定的 SOP 高级设置参数（02 §3.1「参数级微调」机制，角色模板预填）。`parse` 接口不产出该对象（AI 只解析 4 个基础字段）。

| 键                | 类型                                                | 默认值                                                                        | 过滤性质     | 说明                                                                                            |
| ----------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------- |
| companySizeRange  | `{ min?: number, max?: number }`                    | 不限                                                                          | 硬过滤       | 员工数区间；与 `parsed.companySize` 同义，此为结构化口径，两者同时存在时以本字段为准            |
| annualImportRange | enum：`unknown / lt_1m / 1m_10m / 10m_50m / gt_50m` | `unknown`（不过滤）                                                           | 软偏好       | 年进口额区间；公开数据可得性有限，仅影响 `plan_search` 的搜索策略权重与评分理由，不硬性剔除公司 |
| jobTitles         | string[]                                            | `["Purchasing Manager", "Buyer", "Sourcing Manager", "Procurement Director"]` | 联系人优先级 | 职衔匹配白名单，用于 `find_contact` 负责人排序，不过滤公司                                      |
| excludeDomains    | string[]                                            | 空                                                                            | 硬过滤       | 排除域名（已有客户 / 竞品 / 黑名单）；按 §3.6 去重键同口径归一化后比对                          |
| matchThresholds   | `{ high: 85, medium: 60 }`                          | 85 / 60                                                                       | 评分参数     | High/Medium 分档线（口径见 §3.5），与员工 SOP 高级设置参数联动                                  |

### 3.5 客户评分模型口径（v0.2 澄清 §7.2）

- **单一评分源**：`matchPct`（0–100）由工作流 `match_product` 节点 LLM（中档模型）一次评分产出，输入 = 官网摘要 + 目标产品 + 知识中心检索（`scene=lead_match`）的产品要点；输出必须为 Insight Schema `{ value, confidence, reasons[] }`（可解释红线，§4）。
- **scoreLevel 不做二次 AI 判断**：由 `matchPct` 按分档线确定性映射——High ≥ 85、Medium 60–84、Low < 60（分档线即 §3.4 `matchThresholds`，可调）。
- **confidence 独立**表达证据充分度（如官网不可访问 → 低 confidence），不参与分档映射，前端 Tooltip 展示。
- 服务端校验一致性：LLM 返回的 `scoreLevel` 与 `value` 映射不一致时，以 `value` 映射为准。
- 低于 Medium 分档线（默认 <60）不进入联系人发现（对齐 LangGraph 工作流 00 §2.3 阈值分支）；列表 Tab 高/中/低数量即 `score_level` 聚合（`GET /leads/summary`）；头部「今日高价值」= 当日新增 lead 中 `score_level=high` 数。

### 3.6 重复客户判定（v0.2 澄清 §7.3）

**去重键**：`companyDomain`（归一化域名：小写、去 `www.` 前缀）优先；无官网时以 `lower(company_name)` 兜底。MVP 不引入外部企业库，模糊近似（如 `Acme Inc.` vs `Acme GmbH`）由 pg_trgm 相似度辅助判定，阈值实现期校准。三级去重：

| 层级             | 时机                      | 规则                                                                                                                                                                         |
| ---------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 任务内           | 工作流 `dedup_check` 节点 | 同键已在本任务出现过 → 打标跳过，不重复爬取/评分                                                                                                                             |
| 跨任务（发现池） | `save_to_crm_pool` 写入前 | org 内同键存在未转化 lead → **不新建**，合并更新：`match_pct / insight / overview / analyzed_at` 取本次最新，记录来源任务；日志显示「↻ 重复发现」，今日 found 计数不重复累加 |
| 加入 CRM         | `add-to-crm`              | 与 customer 比对（归一化域名 / `lower(company_name)` / 联系人邮箱域）：命中 → 不新建 customer，该 lead 置 `in_crm=true` 并关联已有客户，响应返回 `mappedCustomerId`          |

同键唯一性由 `ai_lead(org_id, company_domain)` 部分唯一索引兜底（见 [ER 03 §2.1](./PostgreSQL%20数据库%20ER%20图/03-AI获客模块.md)）。

### 3.7 获客量与外部调用限额（v0.2 澄清 §7.4）

| 层级   | 上限                                          | 默认值            | 配置位置                                                              |
| ------ | --------------------------------------------- | ----------------- | --------------------------------------------------------------------- |
| 任务级 | 目标发现数 `targetCount`                      | 35                | 创建弹窗（进度分母）                                                  |
| 员工级 | 外部数据源调用日额度 `externalCallDailyLimit` | 200 额度/日       | 员工 SOP 高级设置参数（角色模板预填，org 副本可微调，ER 02 §2.1）     |
| 组织级 | LLM 成本日预算                                | 金额（如 $50/日） | 16 系统设置「AI 模型」（`ai_model_setting.budget_limit`，ER 01 §2.8） |

- **计量口径**：外部调用按工具计权折算「额度」——`web_search` ×1、`crawl_site` ×2、`lookup_contact` ×1；LLM token 成本单独按模型路由计量（16 FR-10）。
- **执行控制**：运行时令牌桶（对齐 LangGraph 工作流 00 §2.3）；额度耗尽 → 任务转 `paused`，日志记 `error`「外部调用日额度已用尽」，站内通知负责人；额度每日 0 点（UTC）重置，次日由用户手动 `resume`（MVP 不自动恢复）。
- **默认值校准**：员工级日额度 200 与 KPI 建议 35 leads/日（02 §3.2）按预估单耗 ≈5 额度/lead 对齐。

## 4. AI 行为边界

- **评分与匹配度必须可解释**：客户评分 / 产品匹配度需能给出判断原因（联动客户 360° 的「AI 判断原因」），不允许只给数字。
- **联系人信息仅限公开商务渠道**：日志中的「查找公开商务联系方式」需遵守数据合规（GDPR/CCPA），禁止使用非公开/爬取的隐私数据。
- **加入 CRM 是状态变更动作**：单个或批量加入 CRM 需遵循操作权限；AI 不自动触发对外触达（开发信发送属于销售中心流程，且需人工审核）。
- 获客任务的执行边界受 AI 审核中心与任务审批策略约束。

## 6. 效果指标（建议）

- 获客产出量：每日发现客户数、高价值客户占比。
- 评分有效性：高价值客户后续回复率 / 转化率显著高于低价值档。
- 加入 CRM 转化率：发现列表 → CRM 的批量转化比例。
- AI 自动化率：无需人工干预完成的任务比例；暂停/纠偏次数。
