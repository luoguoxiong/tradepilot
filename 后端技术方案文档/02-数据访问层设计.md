## 1. Drizzle 工程组织

`packages/db/src/`：

```text
packages/db/src/
├── schema/
│   ├── enums.ts            # pgEnum 全量（ER §4，一个不漏）
│   ├── 01-org-user.ts      # org / user_account / role_permission / mailbox / ... 10 表
│   ├── 02-ai-task.ts       # sop_template / ai_employee / ai_task / ai_task_step / ai_task_log
│   ├── 03-lead.ts          # ai_lead / ai_lead_contact
│   ├── 04-customer.ts      # customer / contact / customer_insight / customer_activity
│   ├── 05-mail-followup.ts # conversation / message / follow_up_* 7 表
│   ├── 06-product-knowledge.ts
│   ├── 07-quote-order.ts
│   ├── 08-approval-data.ts
│   └── relations.ts        # drizzle relations（供查询 API 用；FK 已在表定义）
├── migrations/             # drizzle-kit generate 产物（SQL，纳入 git）
├── rls/                    # RLS 策略 SQL（§4）
├── seed/                   # 注册事务种子（03 §4）+ 预置 SOP 内容（引用 Runtime §4.3 结构）
├── testing/                # 测试工厂
└── index.ts
```

**映射规则**：

| ER 约定（ER 00 §2） | Drizzle 落法 |
|---|---|
| 主键 `id text`（前缀+雪花，应用层生成） | `text('id').primaryKey()`；插入前经 `packages/core/id.ts` 生成，**不用 DB 默认值** |
| `org_id text NOT NULL REFERENCES org(id)` | 每表显式 `references(() => org.id)` |
| 原生枚举 | `pgEnum('task_status', [...])`，名称与 ER §4 一致；新增取值用 `ALTER TYPE` 迁移 |
| jsonb 列 | `jsonb('insight').$type<InsightSchema>()` —— 类型来自 `packages/shared/insight`（Zod 推断），写入前 parse |
| 金额 `numeric(18,2)` | `numeric('amount', { precision: 18, scale: 2 })`；序列化见 §7 |
| 百分比 smallint / 置信度 numeric(4,3) | 同名映射；AI 置信度出参统一转 0~1 number |
| `timestamptz` | `timestamp('created_at', { withTimezone: true })` |
| 部分唯一索引（软删/域名/邮箱） | `uniqueIndex(...).where(sql\`...\`)`（清单见 §6.3） |
| `UNIQUE(org_id, quote_no)` 等复合唯一 | `uniqueIndex('uq_quote_org_no').on(t.orgId, t.quoteNo)` |
| 表达式索引（`gin_trgm_ops`、vector） | drizzle-kit 不支持的走「自定义迁移 SQL」（§2.2） |

## 2. 迁移策略

1. **开发流**：改 `schema/*.ts` → `pnpm drizzle-kit generate`（review 生成 SQL）→ 本地 `migrate` 验证 → 提交。
2. **手写补充迁移**：三类对象 drizzle-kit 覆盖不全，建 `migrations/000X_manual_*.sql` 并入同一迁移链，保证幂等（`IF NOT EXISTS`）：
   - 扩展：`CREATE EXTENSION IF NOT EXISTS vector / pg_trgm;`
   - RLS 策略与角色（§4）；
   - 表达式/部分/向量索引（如 `USING hnsw (embedding vector_cosine_ops)`、`USING gin (company_name gin_trgm_ops)`）。
3. **执行时机**：部署流水线串行步骤 `drizzle-kit migrate`（[09 §5](./09-部署运维与可观测性.md)）；禁止运行时自动迁移。
4. **回滚**：迁移不写 down；错误迁移以「前滚修复」处理（团队约定，避免半回滚态）。

## 3. 连接与驱动

- 驱动：`node-postgres(pg)` + `drizzle-orm/node-postgres`；api 与 worker **各自独立连接池**。
- 池参数基线：api `max=20`；worker 按并发规模 `max=10~30`；`statement_timeout=15s`（api 交互查询）、worker 长事务单独设置；`idle_timeout=30s`。
- 不引入 PgBouncer（`SET LOCAL` 的 RLS 会话语义要求直连或 session 池；租户量级 MVP 不需要）。
- 只读聚合重查询（15 数据中心预聚合）走独立只读副本连接串（P1）。

## 4. 多租户 RLS（应用层 + 数据库双保险）

### 4.1 角色

| 角色 | 用途 | 能力 |
|---|---|---|
| `tradepilot_app` | api/worker 正常业务 | 无 BYPASSRLS，受策略约束 |
| `tradepilot_sched` | Scheduler/Cron 跨租户扫描 | 仅白名单表（`follow_up_task`、`approval_request`、`mailbox`、`ai_task`、`analytics_daily_summary`）SELECT/UPDATE，且仅允许访问扫描必需列集；**不授予业务表通用权限** |
| `tradepilot_migrate` | 仅迁移流水线 | DDL 权限，运行时不可用 |

### 4.2 策略模板（对 ER 00 §2.1 兜底建议的落地）

```sql
ALTER TABLE customer ENABLE ROW LEVEL SECURITY;
ALTER TABLE customer FORCE ROW LEVEL SECURITY;  -- 表 owner 也受约束
CREATE POLICY tenant_isolation ON customer
  USING (org_id = current_setting('app.org_id', true)::text)
  WITH CHECK (org_id = current_setting('app.org_id', true)::text);
-- 对 40 张业务表统一套用；种子/迁移事务用 tradepilot_migrate 执行
```

### 4.3 应用侧注入

```typescript
// packages/db/src/tenant.ts —— 唯一入口
export async function withOrg<T>(orgId: string, fn: (tx: Tx) => Promise<T>) {
  return db.transaction(async (tx) => {
    await tx.execute(sql`SELECT set_config('app.org_id', ${orgId}, true)`); // 事务级
    return fn(tx);
  });
}
```

- **强约束**：repository 方法接收 `tx` 参数；service 层所有跨表/多租户查询必须包在 `withOrg` 内，漏包时 RLS 直接返回空集（fail-closed，测试用例覆盖：跨 org 查询必须为空，[01 §7](./01-工程结构与编码规范.md)）。
- worker 执行任务：TaskRunner 以任务行 `org_id` 打开 `withOrg` 上下文，整图生命周期复用同一事务连接不现实（长任务），按**节点粒度**开事务（节点内多次写共享一个 `withOrg`）。
- Scheduler 跨租户扫描使用 `tradepilot_sched` 角色直连（绕 RLS 仅限白名单表），扫出后逐任务仍以 `withOrg` 执行。

### 4.4 数据范围（scope=self|team|all）与 RLS 的分工

- RLS 只解决「org 之间」；org 之内按 `owner_id` 的裁剪是**应用层职责**（`applyOwnerScope`，见 [03 §5](./03-认证授权与多租户.md)），不走 RLS（同一 org 内策略无法感知请求者角色）。

## 5. 事务规范

| 场景 | 事务边界 | 关键点 |
|---|---|---|
| `POST /auth/register` 种子初始化 | 单事务 | org + admin + role_permission×3 + 默认策略/步骤 + 6 员工（sop_template + ai_employee）+ ai_model_setting（ER 00 §5.5） |
| 客户删除（审批后） | 单事务 | 软删 customer + 写 activity + 审批回写 |
| 知识删除 | 单事务 | 文档行软删（deleted_at/by）+ knowledge_chunk 物理删除（11 §7.2） |
| 审批处置 | 单事务 | approval_request/approval_log 状态 + 回调原业务动作 + `result_ref`（12 §3.3） |
| 消息同步入库 | 按消息批 | conversation upsert + message 插入（external_message_id 幂等）+ follow_up 自动暂停 + 未读计数 |
| 转订单（P1） | 单事务 | 校验 won + 复制明细 + cost_snapshot 原样复制（ER 07 §4） |
| 频控顺延 | 单行乐观锁 | `UPDATE follow_up_task SET next_run_at=... WHERE id=? AND status IN ('ready','scheduled')`，影响行数=0 视为并发冲突放弃 |

- 事务内禁止外呼（HTTP/LLM/SMTP）——外呼在事务外、以状态推进补偿（审批闸门流程天然满足）。
- 长事务上限：单事务 < 5s；超「节点粒度」拆分。

## 6. 索引与查询规范

### 6.1 查询纪律

1. 所有列表查询必须命中索引（`EXPLAIN ANALYZE` 进 PR 自查）；禁 `SELECT *`。
2. 软删表（`customer` / `knowledge_document`）repository 层**默认追加** `deleted_at IS NULL`；引用回溯场景显式走 `withDeleted()` 变体。
3. 多态引用（`biz_type + biz_id`）不 join，由 service 层二次查询组装。
4. 大 jsonb 列（`insight/outputs/input`）不在 WHERE/ORDER 中使用；需要过滤的字段一律落列（ER 00 §2.1 红线）。

### 6.2 索引清单（迁移中必须存在的表达式/部分索引）

| 索引 | 出处 | 用途 |
|---|---|---|
| `uq_customer_org_name (org_id, lower(company_name)) WHERE deleted_at IS NULL` | ER 04 | 同名软删感知唯一 |
| `uq_contact_org_email (org_id, lower(email)) WHERE email IS NOT NULL` | ER 04 | 联系人去重 |
| `uq_ai_lead_org_domain (org_id, company_domain) WHERE company_domain IS NOT NULL` | ER 03 | 获客三级去重兜底 |
| `gin (company_name gin_trgm_ops)`（ai_lead / customer） | ER 03/04 | keyword 模糊搜索 |
| `uq_message_external (mailbox_id, external_message_id) WHERE external_message_id IS NOT NULL` | ER 05 | 邮箱同步幂等 |
| `uq_mailbox_org_account (org_id, lower(account))` | ER 01 | 邮箱唯一 |
| `uq_api_key_hash (key_hash)` | ER 01 | API Key 查找（P1） |
| `knowledge_chunk (document_id, chunk_index)` 唯一 + `hnsw (embedding vector_cosine_ops)` | ER 06 | 检索（[07 §3](./07-知识检索与RAG.md)） |
| `follow_up_task (status, next_run_at)` | Scheduler 扫描 | 到期扫描（[04 §3](./04-任务调度与队列.md)） |
| `ai_task (org_id, status, created_at DESC)` 等 | ER 02 已列 | 列表/排队启动 |

### 6.3 新增索引流程

慢查询 → PR 附 `EXPLAIN ANALYZE` 前后对比 → 手写迁移 SQL 补充；禁止在代码层做内存过滤兜底。

## 7. 序列化与类型转换

| 数据 | 库内 | 出参 | 入参 |
|---|---|---|---|
| 金额 | numeric | 字符串十进制 `"12500.00"` + `currency` | 字符串，service 层 Zod 校验后转 numeric |
| 时间 | timestamptz（UTC） | ISO 8601 UTC（`2026-09-04T14:32:00Z`） | ISO 字符串 |
| 置信度 | numeric(4,3) | number 0~1 | 同 |
| 百分比 | smallint 0–100 | number | 同 |
| ID | text | 原样 | 原样（校验前缀合法，防注入式枚举） |

统一在 `packages/shared/contracts` 的 Zod schema `transform` 完成，repository 不做业务格式化。

## 8. 分页与游标

1. **常规列表**：`LIMIT/OFFSET + COUNT`（`total` 为分页必需，总览 §2.2）；`pageSize ≤ 100` 强制。
2. **任务日志**：`after={logId}` 雪花游标（`id > after ORDER BY id`，`tlog_` 前缀下雪花可比），返回 `hasMore`；SSE 断线补齐同口径（14 §3.3）。
3. **会话消息**：按 `conversation_id + created_at` 倒序分页；同步类批量走 keyset（`WHERE (mailbox_id, external_message_id) > (...)`）避免深分页。

## 9. ID 生成（packages/core/id.ts）

- 格式：`{前缀}{雪花64bit-Crockford}`；前缀对照 ER §2.2 完整表（`org_/usr_/task_/tlog_/cus_/msg_/...`）。
- 雪花：41bit 毫秒 + 10bit 机器位（部署时按 `WORKER_INDEX` 环境变量分配）+ 12bit 序列；单机单调，**同毫秒内递增**，保证日志 `after` 游标语义。
- 时钟回拨：检测到回拨 > 5ms 抛错拒发（防止日志游标乱序）；< 5ms 自旋等待。
