## 1. 模块定位

### 1.1 页面目标

统一沉淀企业的客户资产：潜在客户、正式客户、联系人与全部活动，支撑 AI 与人工的协同管理（阶段推进、下一步动作）。

### 1.2 目标用户

- 一线业务员：管理自己负责的客户
- 外贸经理：查看团队客户资产（负责人维度）

## 3. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-01 | 四类页签 | 潜在客户 / 正式客户 / 联系人 / 全部活动 |
| FR-02 | 搜索与筛选 | 关键词搜索 + 国家 / 状态 / 负责人筛选 |
| FR-03 | 添加客户 | 「+ 添加客户」手工录入入口；同时承接 AI 获客「批量加入 CRM」的落库 |
| FR-04 | 客户列表字段 | 客户名、阶段、最近活动时间、下一步动作 |
| FR-05 | 客户阶段管理 | 阶段语义色：🔵 New Lead → 🟡 Contacted → 🟢 Negotiation → 🔴 Cold（Cold 客户展示「AI 建议重新激活」） |
| FR-06 | 下一步动作 | 列表内直接展示下一步（发送报价 / Follow-up #2 / 发送开发信），点击进入对应流程 |
| FR-07 | 客户详情跳转 | 点击客户进入 [客户 360°](./04-客户360°.md) |

---

## 4. AI 行为边界

- 「AI 建议重新激活」仅为建议，不自动发送任何邮件。
- 客户阶段由人工或明确的业务规则推进；AI 不得擅自变更客户阶段。
- 客户删除 / 合并为高危操作，必须经 AI 审核中心人工批准。

| 依赖模块 | 用途 |
|---|---|

| 04-客户360° | 客户详情页 |
| 06-AI销售工作台 / 07-AI自动跟进 | 最近活动、下一步动作的执行载体 |
| 09-报价中心 | 「发送报价」下一步跳转 |
| 12-AI审核中心 | 客户删除等高危操作审批 |

---

## 6. 效果指标（建议）

- 客户阶段推进率（New Lead → Contacted → Negotiation 的流转效率）。
- Cold 客户重新激活率。
- 客户资料完整度（联系人、阶段、下一步均有值的客户占比）。

---

## 7. 待澄清问题

1. 「潜在客户」与「正式客户」的判定规则（首次成交自动升级？）。
2. 负责人分配机制：AI 发现的客户默认负责人是谁，如何转交。
3. 潜在客户 / 联系人 / 活动页签的字段清单与批量操作。
