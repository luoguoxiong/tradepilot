## 1. 队列拓扑（BullMQ）

| 队列 | 承载任务类型 | 并发基线 | 说明 |
|---|---|---|---|
| `q:lead_hunting` | lead_hunting | 每 worker 2 | 循环搜索型，长任务（分钟级） |
| `q:email_reply` | email_reply | 每 worker 5 | 单邮件触达，秒~十秒级 |
| `q:follow_up` | follow_up | 每 worker 5 | 由 Scheduler 到期投递 |
| `q:knowledge_index` | knowledge_index / product_analysis（P1） | 每 worker 2 | 批处理型 |
| `q:analysis` | business_analysis / order_monitor（P1） | 每 worker 1 | 长任务，检查点密集 |
| `q:email_sync` | 邮箱收发同步（系统任务，不落 ai_task） | 每 worker 3 | 按 mailbox 周期/触发（[06 §2](./06-外部集成设计.md)） |
| `q:notify` | 站内/邮件通知、Webhook 出站 | 每 worker 5 | 削峰 |

- `task_type` 与队列一对一映射；新增类型 = 新队列 + 注册表项。
- BullMQ job `jobId = taskId`（同 id 活跃 job 唯一，天然防重复入队）；`removeOnComplete/removeOnFail` 开启（痕迹在 DB，不在 Redis）。

## 2. 入队路径

```text
① API 触发（POST /lead-tasks、POST /tasks、收件来信触发 email_reply）
② Scheduler 到期投递（follow_up_task.next_run_at）
③ delayed job（ai_task.scheduled_at 非空 → BullMQ delayed）
④ 手动重试/重新生成（retry_of / regenerate_of 新任务）
```

**入队判定（POST /tasks，14 §3.2 口径）**：

```text
员工 status ∈ {idle} 且 org running < 10 → 投递队列，ai_task.status='running'
否则 → ai_task.status='scheduled' 落库（不投递），由 Dispatcher 启动（§3.3）
响应 { taskId, status: 'running' | 'scheduled' }
```

## 3. Scheduler 与 Dispatcher（apps/worker）

### 3.1 组成

| 组件 | 周期 | 职责 |
|---|---|---|
| `FollowUpScanner` | 每 10s | 扫 `follow_up_task`：`status ∈ ('ready','scheduled') AND next_run_at <= now()`（索引 `idx_ftask_status_next_run`）→ 频控预检 → 建 ai_task(follow_up) 入队 |
| `Dispatcher` | 每 2s | 启动排队任务：员工空闲 + org 并发未满 → 队首 FIFO（`created_at`/`scheduled_at`）投递 |
| `DelayedJobReconciler` | 每 60s | 对账：`ai_task.scheduled_at` 到期但无对应 delayed job（Redis 丢失兜底）→ 补投 |
| `ApprovalExpiryScanner` | 每 60s | 见 §4 |
| `ZombieReaper` | 每 60s | 见 §5.4 |
| `MailboxSyncScheduler` | 每 5min（可配） | 触发各 mailbox 增量同步（[06 §2](./06-外部集成设计.md)） |
| `QuotaReset` | 每日 00:00（org 时区） | 重置外部调用日额度（[06 §3](./06-外部集成设计.md)） |

- 扫描角色：`tradepilot_sched` 专用受限连接（[02 §4.1](./02-数据访问层设计.md)）；`FOR UPDATE SKIP LOCKED` 领取，多 worker 实例部署安全。

### 3.2 频控预检与顺延（唯一实现点：`packages/core/time-window.ts`）

```text
L = 该客户最近一次 outbound 邮件时间（message.direction='out' and status='sent'，含人工）
target = max(当前 next_run_at, L + minTouchIntervalDays 天)
next_run_at' = 对齐发送窗口(target, org.send_rules.sendWindow, org.timezone)
  当地 < 09:00 → 当日窗口起点；≥ 18:00 → 次日窗口起点；窗口内 → 保持
不满足频控 → next_run_at 顺延写入 + follow_up_execution(skipped, skip_reason='frequency_capped')，不入队
```

- `minTouchIntervalDays` 实时读 `org.send_rules`（16 FR-12）；顺延用单行乐观锁（[02 §5](./02-数据访问层设计.md)）。
- `schedule_next` 节点（图内）复用同一 `对齐发送窗口` 函数——**排期单一写入口**：Scheduler 预检 + schedule_next，二者均不触碰非 `scheduled` 状态任务（Runtime §4.7）。

### 3.3 并发闸门

| 限制 | 实现 |
|---|---|
| 单员工并发 = 1 | Dispatcher 启动前查该员工 `running` 任务数（`idx_ai_task_org_employee`），=1 则跳过；启动即 `UPDATE ai_task SET status='running', started_at=now() WHERE id=? AND status='scheduled'` 乐观锁，影响行数=0 放弃（双实例安全） |
| org 总并发 = 10 | Dispatcher 统计该 org `status='running'` 数（`idx_ai_task_org_status`），≥10 排队；MVP 常量，配置列后续 |
| waiting_approval 不占并发 | 并发仅统计 `running`（Runtime §4.7 挂起即冻结） |

### 3.4 delayed job 约定

- `ai_task.scheduled_at` 非空 → 入队时加 BullMQ delayed（delay = `scheduled_at - now`，jobId=taskId）。
- 任务取消/暂停 → `job.remove()`；Reconciler 每 60s 对账兜底。

## 4. 审批超时扫描（ApprovalExpiryScanner）

```text
approval_request WHERE status='pending' AND expires_at < now()
→ 单事务（[02 §5]）：
  approval_request.status='expired'（终态）+ approval_log(action='expired')
  + 邮件提醒经理一次（q:notify，防重：log 存在则不再发）
  + 级联 ai_task.status='failed'（error='approval_expired'，outputs 已留存草稿）
  + follow_up_task.status='paused'（转人工）
  + SSE status 事件
```

- `expires_at` 默认 48h（16 可配）；处置接口对 expired 终态返回 `40901`（不可再处置）。

## 5. 任务执行骨架与可靠性

### 5.1 TaskRunner 流程（worker）

```text
领取（BullMQ processor）
→ 乐观锁置 running（防重复）→ 员工 status='working'
→ 建 ai_task_step 占位（seq=1）→ withOrg(orgId) 加载图并执行（[05 §2]）
→ 每节点完成：写 step/log/progress → PUBLISH task:{id}:events
→ 终态：写 outputs/finished_at → 员工 status 回写 idle/working → SSE done
→ job 完成
```

### 5.2 幂等三层

| 层 | 机制 |
|---|---|
| 入队 | jobId=taskId；API 层请求幂等键可选（Idempotency-Key header → Redis 10min） |
| 领取 | DB 乐观锁（status 条件更新）+ `FOR UPDATE SKIP LOCKED`（Scheduler 侧） |
| 副作用 | 工具幂等键 `taskId+nodeId`（+`messageHash` for email_send），重试不重复外发（Runtime §7） |

### 5.3 重试与失败

- 节点级：LLM 自动重试 2 次、工具按工具配置（Runtime §4.8），在图/工具包装层实现，不经 BullMQ attempts。
- 任务级：BullMQ `attempts=1`（不自动重投）；失败 → `status='failed' + error`；手动重试/重新生成 = 新任务（`retry_of` 溯源）。
- 转移：`transfer-to-human`（P1）= 暂停图 + 写 outputs 交接摘要。

### 5.4 僵尸与暂停恢复

- ZombieReaper：`running` 且 `started_at` 超 30min 且 Redis 心跳（worker 每 30s 写 `task:{id}:heartbeat`）缺失 → 置 `failed('timeout')`（可手动重试）。
- 手动暂停：API 写 `status='paused'` → Worker 订阅控制事件中断图 → checkpointer 已存；恢复 = 重新入队，从最近检查点续跑当前节点（工具幂等防重复）。
- 优雅停机：worker 收 SIGTERM → 停止领新 job → 等当前节点检查点落盘（最长 60s）→ 退出；未完 job 由 BullMQ stalled 机制重投。

## 6. SSE 管道（事件与断线补齐）

### 6.1 事件流

```text
Worker（节点完成/状态变更）
  → DB 写入（step/log/ai_task.progress_pct/current_step/status）
  → Redis PUBLISH task:{taskId}:events  {type:'log'|'progress'|'status'|'done', payload, seq}
API SSE Handler（GET /tasks/{id}/stream）
  → 鉴权（?token=）→ SUBSCRIBE 频道（先订阅，缓冲到达事件）
  → 回放：按 ?after={logId} 从 DB 补齐增量日志 → flush 缓冲（去重：logId/seq）
  → 推送：log/progress/status/done 四类事件（契约 = 14 §3.4）
  → 心跳：每 15s `: ping`；客户端断开 → UNSUBSCRIBE
```

- 先订阅后回放保证不丢事件；`seq`（雪花）供客户端去重。
- 事件类型定义集中在 `packages/shared/sse`，与接口文档 14 §3.4 逐字段对齐。
- 连接上限：单用户 ≤ 10 条 SSE；org ≤ 200（超限 `42901`）。

### 6.2 兜底

SSE 不可用时前端轮询 `GET /tasks/{id}/logs?after=` + `GET /tasks/{id}`（接口已定）；网关需配置 `proxy_buffering off` / 响应头 `text/event-stream`。

## 7. 与审批闸门的衔接

- 图执行到 medium/high 工具节点 → Gate 判定（[05 §4](./05-AgentRuntime与LLM网关.md)）→ `interrupt()` → checkpointer 持久化 → ai_task `waiting_approval` + linked_approval_id → SSE status 事件。
- 审批处置（12 接口）→ worker 收到 `Command{resume}`（经 `q:follow_up` 控制通道或 BullMQ resume job）→ 图恢复 → **新鲜度校验**（email_reply 重查会话 / follow_up 重跑 check_replied）→ 真实执行。
- 挂起期间：follow_up_task.status 同步 `waiting_approval`、`next_run_at` 冻结；Scheduler 扫描条件天然排除（仅扫 ready/scheduled）。
