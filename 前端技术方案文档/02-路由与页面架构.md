## 1. 布局体系

### 1.1 DefaultLayout（登录后主布局）

对齐[产品总览 §3/§7](../产品需求文档/00-产品总览与MVP规划.md)：

```text
┌────────────────────────────────────────────────────────────┐
│ GlobalHeader (64px)：Logo · 全局搜索 · 通知铃(含待审数) · 用户│
├──────────────┬─────────────────────────────────────────────┤
│ GlobalSider  │  <router-view> + <router-view name="detail">│
│ (240px，可折叠)│  内容区最大宽 1600px，水平居中               │
│ 11 个一级菜单 │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- Sider 菜单由路由表**自动生成**（`meta.menu !== false`），按 `features.ts` 过滤（§5）；
- Header 全局搜索：聚合入口（客户/任务/产品），P0 先做客户与任务快捷跳转，防抖 300ms；
- Header 通知铃：轮询待审数量（见 [03 §5](./03-状态管理与数据请求.md)），点击跳转审核中心。

### 1.2 BlankLayout

用于登录、注册、企业初始化向导（16 v0.4：四步向导「注册 → 上传产品资料 → 连接邮箱 → 完成」）。

## 3. 导航守卫链

`src/router/guards.ts` 按序装配：

```text
1. 认证守卫：无 token 且 meta.public 不成立 → /login?redirect=...
2. 初始化守卫：登录后取 authStore.onboarding.currentStep，
   < 4 且目标非 /onboarding → 强制跳 /onboarding（16 v0.4 语义）
3. 角色守卫：meta.roles 不含当前 role → 403 页（UX 裁剪，服务端 40301 为权威）
4. 标题与时区：setDocumentTitle(meta.title + orgName)；加载 org 时区供 dayjs 渲染
```

- 登录成功：`POST /auth/login` 返回 `token + onboarding.currentStep`，写入 authStore 后按第 2 条逻辑决定去向；
- Token 失效：请求层收到 `40101` → 清会话 → 守卫拦截（见 [03 §4](./03-状态管理与数据请求.md)）。

## 4. 页面承载模式

### 4.1 列表页统一模式（ProTable）

CRM / 发现列表 / 跟进任务 / 审批 / 知识文档等产品页面统一由 `ProTable` 封装承载：

- 声明式列定义（字段/枚举渲染/排序）；筛选区由 `FilterBar` schema 生成；
- 分页/排序参数与[接口规范 §2.3](../产品需求文档/页面级字段与接口文档/00-总览与接口规范.md) 对齐（`page/pageSize/keyword/sortBy/sortOrder`）；
- 内置数据范围选择器 `ScopeSelect`（`scope=self|team|all`，按角色显隐，[05 §2](./05-权限与安全设计.md)）；
- 批量操作：多选 → 底部操作条（如 CRM 批量改派/删除走二次确认 + 40301/40901 错误透出）。

### 4.2 详情页页签模式（客户 360°）

- 8 页签：Overview / Contacts / Products / Conversations / Quotes / Orders / Activities / AI Insights；
- 页签内容**路由化子路由**（`/customers/:id?tab=overview`），数据懒加载——切到该页签才发首个请求；
- Quotes / Orders 页签与「去创建报价」空态按 `features.ts` 隐藏（D6/D7，见 §5）；
- Products 行为按特性分流：P0 行点击展开行内侧滑（insight/overview），P1 启用后跳产品详情。

### 4.3 抽屉优先原则

详情类操作（审批处置、任务详情、客户快速查看、联系人编辑）默认 **Drawer**，不新增路由层级；需要分享/收藏的实体（客户、报价、订单）用独立路由页。

## 5. P0 降级矩阵的前端渲染策略

### 5.1 特性开关实现

```ts
// src/features.ts —— 编译期固化（VITE_FEATURES_PROFILE = p0 | p1）
export const features = {
  quotes: false,   // 09 报价（P1）
  orders: false,   // 10 订单（P1）
  products: false, // 08 产品（P1）
  manager: false,  // 13 外贸经理（P1）
  taskCenter: false, // 14 任务中心（P1，接口已用）
  dataCenter: false, // 15 数据中心（P1）
} as const
export type FeatureKey = keyof typeof features
```

- P1 交付时将对应项置 `true` 即恢复（与 PRD「由交付版本决定」一致）；`features.ts` 的 diff 即交付清单；
- 路由、菜单、页签、卡片、推荐动作四处读取同一份常量，保证口径一致。

### 5.2 三种降级手段与组件支撑

| 手段 | 实现 | 典型落点 |
|---|---|---|
| 隐藏（默认） | `v-if="features.xxx"` 不渲染；菜单/路由直接过滤 | D1 KPI 两卡、D3 每日报告入口、D6 页签、D10 无源 Tab、D8「创建报价」建议 |
| 置灰占位 | `<ComingSoon text="即将上线"/>`：卡片保留、入口禁用 | D4 外贸经理卡片（`idle` + statusDetail）、D12 设置子菜单占位 |
| 功能内降级 | 保留功能、数据源收窄 | D2 今日待处理仅已启用类别、D5 `currentTask` 轻量对象、D9 知识中心为唯一依据来源、D7 行点击行为分流、D11 手动上传 |

## 6. 页面缓存与保活

- `<keep-alive include>` 缓存高频列表页（CRM、发现列表、审批），key 含路由 query 中的页签参数，避免返回丢失筛选状态；
- 客户 360° 页签不进 keep-alive（数据新鲜度优先），切页签即静默 refetch（staleTime 见 [03 §5](./03-状态管理与数据请求.md)）；
- 表单类页面（策略编辑、报价编辑）离开时 `onBeforeRouteLeave` 拦截未保存变更。
