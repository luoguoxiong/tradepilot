# AI 外贸跟单助理（order-followup）测试计划

- 版本：v1（对应 PRD v1 / design-v1）
- 日期：2026-09-04

## 一、测试范围与红线场景

### 范围
订单导入解析（AI）、订单台账/详情、进度节点、单证生成（PI/Invoice/PL）、异常引擎、邮件草稿与 SMTP 发送、设置。

### 红线场景（P0，零容忍，每版必跑）
| # | 红线 | 验证方式 |
|---|------|---------|
| R1 | 单证数字必须来自订单确认数据：行金额=数量×单价、Σ行=总额、大写金额与数字一致 | 确定性单测 + 校验器阻断测试 |
| R2 | 解析结果未经人工确认不得入订单库 | API 测试：import 只写 order_imports，confirm 才建单 |
| R3 | 邮件不得编造事实：含未填占位符即拒绝；发送必须人工确认 | Prompt 校验器测试 + 发送端点仅由显式 POST /send 触发 |
| R4 | SMTP 密码 write-only 且加密存储 | 设置 API 测试：不下发密码；加解密回环单测 |
| R5 | 异常规则不漏报（提醒覆盖率） | 异常引擎单测：四类规则×边界日期 |

## 二、测试策略（分层）

1. **确定性逻辑单测**（100% 精确断言，node:test）：`amountInWords` 英文大写金额（含 0/分/百万位/JPY 无小数场景由币种表控制）、`validateDoc` 一致性校验、`buildDocData` 金额计算、异常规则四类、解析结果结构与置信度校验。
2. **API 集成测试**（隔离 DB + Mock LLM）：建单校验、单证端点阻断（校验不过 code=2 + issues）、邮件草稿生成失败路径（占位符 → 重试 → 报错）、设置读写、重复导入确认幂等。
3. **AI 评估集**（真实 DeepSeek，人工标注 golden）：订单解析字段准确率（要素断言：字段存在且值正确；LLM 输出与 golden 逐字段比对）。
4. **E2E 冒烟**（浏览器）：异常看板/订单台账渲染、详情页交互、设置页。

## 三、评估集设计

- `eval-sets/order-parse-golden-v1.jsonl`：8 条样本，覆盖——
  - 结构化 PI 文本 / 混乱邮件文本 / CSV 表格 / 中文订单 / 多产品行 / 字段缺失（null 期望）/ Incoterms 变体（FOB/CIF）/ 付款方式表述
- 断言方式：逐字段等值比对（日期标准化、币种大写、数值相等），输出字段命中率指标；目标 ≥90%。
- 回流规则：本轮 badcase 追加至 v1 文件并标注来源（只增不减）。

## 四、环境与数据

- 隔离 DB（/tmp 临时库）；Mock LLM（本地 HTTP 服务，模式参照一期 integration.test）；
- 真实 LLM 评估：server/.env 的 DeepSeek key，仅跑解析评估集（8 次调用，成本可控）；
- E2E：start.sh 拉起的 8787 + 5173。

## 五、准入/准出

- 准入：server tsc + web vue-tsc 构建通过；一期既有 24 用例回归通过。
- 准出（Go）：P0=0、P1=0、解析评估集字段命中率 ≥90%、红线 R1-R5 全部 PASS。

## 六、风险与应对

- 解析评估依赖真实模型输出非确定性 → 每字段以「本轮实测值 vs golden」人工复核后再计入命中率，概率性偏差标注。
- 扫描件 PDF 不支持是已知边界（PRD 明示）→ 作为 P3 观察项，不做阻断。
