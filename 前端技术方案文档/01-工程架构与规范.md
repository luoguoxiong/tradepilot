## 1. 工程形态

- **单应用工程**（非 monorepo）：MVP 阶段一个 Web 端，不引入多包管理成本；
- 包管理：**pnpm**（Node 20 LTS）；
- 脚手架：`create-vue`（官方模板，内置 Vite + TS + Router + Pinia + ESLint/Prettier 基线）。

约定：

- `features/<module>/` 内聚该模块的 `views`、模块私有组件、模块内 api/query；跨模块复用一律上提到 `components/`；
- P1 模块目录与路由**先建骨架占位**（懒加载入口 + 空态），由 `features.ts` 控制可见性；
- `api/types` 与[页面级字段与接口文档](../产品需求文档/页面级字段与接口文档/00-总览与接口规范.md)逐字段对齐，接口变更 = 文档先行 + 类型同步。

## 3. 编码规范

| 类别 | 约定 |
|---|---|
| SFC | 一律 `<script setup lang="ts">`；`defineProps/defineEmits` 用类型声明式；单文件 ≤ 300 行，超出拆子组件/composable |
| 命名 | 组件多词 PascalCase（`InsightCard.vue`）；composable `useXxx`；常量 UPPER_SNAKE；接口类型 `XxxResp / XxxReq` |
| Props | 必填/默认值显式声明；禁止跨层透传超深 props（>2 层改用 provide/inject 或 store） |
| 样式 | 组件内 `scoped` SCSS；颜色/间距禁止字面量，一律引用 `styles/tokens.scss` 的 CSS Variables |
| 枚举 | 状态值渲染一律走 `utils/enum-map`（值 → 文案 i18n key + 语义色 token），禁止视图内散落三元判断 |
| 时间 | 提交后端一律 ISO 8601 UTC；渲染一律 dayjs 本地化；禁止手写格式串散落 |
| 金额 | 后端字符串十进制 `amount`，前端展示用 `formatMoney(amount, currency)`，计算用 decimal 库（decimal.js），禁止 float 运算 |
| TS | `strict: true`；禁止 `any`（第三方缺类型才允许局部 `unknown` 收窄）；接口响应类型必标 |

## 4. Git 与协作规范

- 分支模型：`main`（保护，跑发布）+ `feat/fix/chore-*` 短生命周期分支，PR 合入；
- 提交：Conventional Commits（`feat(crm): ...`），commitlint 强校验；
- 提交前钩子（husky + lint-staged）：ESLint --fix → Prettier → Stylelint → `vue-tsc --noEmit`；
- CR 门槛：涉及 `api/types`、`features.ts`、权限指令的改动必须至少一人评审。

## 5. 环境与构建

### 5.1 环境变量

| 变量 | 示例 | 说明 |
|---|---|---|
| `VITE_API_BASE` | `/api/v1` | 走同域反代，避免 CORS；如跨域部署则填完整 URL |
| `VITE_SENTRY_DSN` | — | 生产错误上报 |
| `VITE_RELEASE` | git sha | sourcemap 关联与灰度排查 |
| `VITE_FEATURES_PROFILE` | `p0` / `p1` | 决定 `features.ts` 生效档位 |

> `features.ts` 按 `import.meta.env.VITE_FEATURES_PROFILE` 在构建期固化，详见 [02 §5](./02-路由与页面架构.md)。

### 5.2 Vite 配置要点

- 别名：`@` → `src/`；
- 开发代理：`/api` → 后端开发网关（SSE 代理需关闭响应缓冲 `configure(proxy) { proxy.on('proxyRes', p => p.headers.connection = 'keep-alive') }` 并设置 `proxy.timeout` 足量）；
- 分包：`manualChunks` 将 `element-plus`、`echarts`、`tiptap` 拆 vendor chunk；
- 构建产物：gzip + brotli 双压缩，sourcemap 仅 staging 保留。

### 5.3 部署

- 产物为纯静态资源：Nginx / CDN 托管，`index.html` 不缓存（`no-cache`），静态资源带内容 hash 长缓存；
- Nginx 需配置：history 路由 fallback（`try_files ... /index.html`）、`/api` 反代（含 SSE：`proxy_buffering off`）、安全响应头（CSP / X-Frame-Options，见 [05 §4](./05-权限与安全设计.md)）；
- CI 流水线：`install → lint → type-check → test → build → 部署 staging → 手动确认发 prod`。

## 6. 多语言与本地化基线

- MVP 语言集：`zh-CN` / `en`（org.defaultLanguage 决定默认，用户可手动切换，偏好存 localStorage）；
- 文案 key 按模块前缀：`crm.stage.new_lead`、`approval.action.approve`；
- AI 生成内容的 `language` 字段按原文渲染，不参与 i18n（接口规范 §2.1）；
- 默认语言兜底：无信号时 zh-CN（与产品「多语言回复」口径独立，UI 语言 ≠ 邮件语言）。
