## 3. 接口详细定义

### 3.1 GET /api/v1/conversations

请求参数：`keyword`、`priority`、`unreadOnly`、`mailboxId`（FR-11 多邮箱聚合）、分页。响应 `items[]`：1.1 字段。

### 3.2 POST /api/v1/conversations/{id}/ai-draft

请求：`{ basedOnMessageId: "msg_9", instruction?: "强调 MOQ 优势" }`

响应 `data`：

```json
{
  "draftId": "msg_10", "content": "Dear John, Thank you for your interest…MOQ starts from 500 pairs…",
  "basedOnMessageId": "msg_9", "generatedAt": "2026-09-04T14:40:00Z",
  "citations": [
    { "docId": "doc_3", "docName": "Carbon Fiber Catalog.pdf", "chunkId": "chk_12" }
  ]
}
```

> 边界：`citations` 为空表示知识库无依据，前端提示用户补充资料，禁止编造参数（需求文档 §4）。

### 3.3 POST /api/v1/conversations/{id}/send

请求：`{ messageId, content }`（content 为最终编辑后内容）

响应（两种分支）：

```json
// A. 低风险策略直接发送
{ "messageId": "msg_10", "status": "sent", "sentAt": "…" }
// B. 审批策略要求审核
{ "messageId": "msg_10", "status": "draft",
  "approval": { "approvalId": "appr_21", "approvalType": "email_send", "status": "pending" } }
```

### 3.4 POST /api/v1/copilot/suggestions/apply

请求：`{ conversationId, suggestionIds: ["sg_1", "sg_2"], mode: "insert_draft" | "create_tasks" }`

响应：`{ draftContent?（插入后的草稿）, taskIds?[] }`。

建议分流（需求 §7 已澄清）：**内容型建议**（回复报价范围 / 询问数量 / 推荐产品）走 `insert_draft`，逐条插入合并为要点；**流程型建议**（创建报价 / 预约跟进）走 `create_tasks`，生成任务或跳转对应模块；不做一键自动执行多动作。

### 3.5 POST /api/v1/conversations/{id}/ask-ai

请求：`{ question: "客户上次报价多少？" }` → 响应 `{ answer, citations[] }`（RAG 检索客户会话/知识库）。

## 4. 联动与边界

- **AI 只起草，人决定发送**：`send` 接口由服务端按企业审批策略决定分支 B（邮件发送属审核类型）。
- **禁止编造业务参数**：草稿生成服务端仅从产品/知识结构化数据取数并回填 `citations`；无依据时返回 `content` + `missingKnowledge: true` 提示。
- 用户修改后的草稿作为反馈沉淀（`PUT /messages/{id}` 记录编辑差异，用于采纳率统计）。
- 邮箱通道来自 [16-系统设置](./16-系统设置.md)（IMAP/SMTP）；「回复报价范围」动作关联 [09-报价中心](./09-报价中心.md)。
- **收件箱与多语言**（需求 §7 已澄清）：会话列表即多邮箱来信聚合视图（FR-11，同步口径见 ER 05）；草稿语言跟随会话最近一条 in 消息的 `language`，无信号默认英文；邮件模板 P1 占位（AI 草稿已覆盖 MVP 场景）。
