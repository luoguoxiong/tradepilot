## 3. 接口详细定义

### 3.1 POST /api/v1/orders

请求：`{ customerId, items[], deliveryDate, paymentTerms, fromQuoteId? }`
响应：`{ orderId, orderNo: "SO-20260904-001", status: "pending_payment" }`。
`fromQuoteId` 传入时自动带入报价明细与金额，报价需为 `won` 状态。

### 3.2 PUT /api/v1/orders/{id}（订单变更）

请求：`{ deliveryDate?, amount?, items? }` —— AI 身份调用直接 `40301`；人工调用亦返回：

```json
{ "approvalId": "appr_41", "approvalType": "order_change", "status": "pending" }
```

变更在审批通过后才生效（未生效前详情展示「变更审批中」）。

### 3.3 PUT /api/v1/orders/{id}/progress

请求：`{ progress: { poConfirmed?, payment?, productionPct?, shipping? } }` → 响应 `{ status, progress }`。

口径（需求 §7 已澄清）：**手工填报唯一入口**，每次更新写 `order_progress_log`（历史可追溯）；ERP/MES 对接列后续集成需求专项。风险判定为服务端规则：`plannedPct` 按时间线性推导（创建日 → 交期，`planSource='linear_by_time'`），`actualPct` 落后超过阈值 → `risk=at_risk`，`delayDays` 按落后比例估算；AI 仅负责原因表达与建议生成。

### 3.4 GET /api/v1/orders/{id}/risk

响应 `data`（1.3 结构）：

```json
{
  "delayDays": 3, "reason": "生产进度低于计划",
  "evidence": { "plannedPct": 80, "actualPct": 60, "planSource": "production_plan" },
  "suggestions": [
    { "suggestionId": "sg_1", "type": "internal", "label": "联系生产负责人" },
    { "suggestionId": "sg_2", "type": "internal", "label": "调整生产计划" },
    { "suggestionId": "sg_3", "type": "customer", "label": "准备客户沟通邮件" } ]
}
```

### 3.5 POST /api/v1/orders/{id}/risk/execute

请求：`{ suggestionIds: ["sg_1", "sg_2"] }`

响应（按建议类型分流）：

- `internal`（对内动作）→ `{ taskIds: ["task_2001"] }`（按权限可自动执行，见 [14-AI任务中心](./14-AI任务中心.md)）
- `customer`（对客户承诺类）→ `{ approvalId }`（需人工审核后发出）

### 3.6 POST /api/v1/orders/{id}/risk/draft-email

响应：`{ draftId, conversationId, content }` —— 生成延期沟通草稿进入 [06-AI销售工作台](./06-AI销售工作台.md)（新交期承诺需人工确认后发送）。

## 4. 联动与边界

- **延期预警必须给可核查原因**：`evidence.plannedPct/actualPct` 为必填；无数据时 `risk=normal` 不给风险标记。
- `delayDays` 前端必须标注「估算」；AI 不预测汇率走势与绝对交期。
- 生产进度：手工填报唯一入口（`PUT /progress`，写 `order_progress_log`）；风险判定为服务端规则（进度差阈值 + 时间线性推导计划），AI 仅负责原因表达与建议生成（需求 §7 已澄清）；ERP/MES 对接、PI/CI 单证、物流轨迹均列后续专项，不在 10 v0.1 范围。
- 订单记录回写客户 360° Orders 页签（[05-CRM客户中心](./05-CRM客户中心.md)）。
