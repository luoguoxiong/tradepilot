## 4. 总体架构

```mermaid
flowchart TB
    subgraph 客户端
        W[Web 前端 Vue 3]
    end

    subgraph 接入层 apps/api
        REST[REST /api/v1<br/>NestJS]
        SSE[SSE 网关<br/>/tasks/{id}/stream]
        AUTH[JWT / RBAC / RLS 上下文]
    end

    subgraph 调度层 apps/worker
        SCH[Scheduler<br/>follow_up 扫描·频控预检·排队启动]
        CRON[Cron 扫描器<br/>审批超时/邮箱同步/额度重置]
    end

    subgraph 运行时 packages/runtime
        TR[TaskRunner]
        EX[LangGraph.js 图执行]
        TL[Tool Registry]
        AG[Approval Gate]
        LG[LLM Gateway]
    end

    subgraph 数据层
        PG[(PostgreSQL 16<br/>业务表 + checkpointer + pgvector)]
        RD[(Redis 7<br/>BullMQ + Pub/Sub + 令牌桶)]
        OSS[(对象存储<br/>文档/附件)]
    end

    subgraph 外部
        MAIL[邮箱 Gmail/Outlook/SMTP-IMAP]
        SEARCH[搜索/抓取供应商]
        LLM[LLM 供应商]
    end

    W --> REST
    REST --> AUTH --> PG
    REST --> RD
    SCH --> RD
    CRON --> PG
    RD --> TR --> EX
    EX --> TL --> AG
    EX --> LG --> LLM
    TL --> MAIL & SEARCH
    EX -- step/log/status --> PG
    EX -- 事件 --> RD
    RD -- Pub/Sub --> SSE
    TR & EX --> PG
    EX --> PG
    LG --> PG
    TL --> OSS
```

- **双进程模型**：`apps/api` 只做鉴权、校验、入队、查询与 SSE 推流，不执行图；`apps/worker` 消费队列并驱动图执行，按队列类型水平扩容。
- **实时链路**：Worker 写库后向 Redis Pub/Sub 发布 `task:{id}:events`；API 侧 SSE 订阅推送，断线用 `GET /tasks/{id}/logs?after=` 补齐（[04 §6](./04-任务调度与队列.md)）。
- **多租户**：`org_id` 贯穿 API（JWT）→ 队列 job → 图状态 → 工具查询；PostgreSQL RLS 作行级兜底（[02 §4](./02-数据访问层设计.md)）。

## 5. 关键架构决策（ADR 摘要）

| # | 决策 | 理由 | 代价与约束 |
|---|---|---|---|
| ADR-1 | ORM 选 **Drizzle** | 大量 jsonb / 原生枚举 / 部分唯一索引 / RLS（`SET LOCAL`）需要贴近 SQL 的控制力；类型推导好 | 无自动关系加载，关联显式 join |
| ADR-2 | 队列选 **BullMQ（OSS）**，org 并发=10 用调度器闸门实现 | 与 Node/TS 生态契合，delayed job 天然支持定时任务；BullMQ Pro 的 groups 付费，不引入 | 并发闸门自研（[04 §3.3](./04-任务调度与队列.md)） |
| ADR-3 | 实时推送选 **SSE** 而非 WebSocket | 接口文档 14 §3.4 已定 SSE 契约；单向推送够用，断线补齐依赖 logs 增量接口 | 仅任务域推送；后续 IM 实时需求另议 |
| ADR-4 | 向量检索 **pgvector 单库**，不引入独立向量库 | 数据量（企业知识文档）远未到独立向量库阈值；与业务表同库事务、同备份 | 检索规模到千万 chunk 级再评估 |
| ADR-5 | RLS + 应用层双保险 | ER 00 §2.1 建议的兜底；多租户隔离不能只靠一处 | worker 跨租户扫描需专用受限角色（[02 §4.4](./02-数据访问层设计.md)） |
| ADR-6 | ID = 前缀 + 雪花（应用层生成） | 接口文档 §2.4 / ER §2.2 已定；`after={logId}` 增量依赖雪花时序 | worker 多实例需分配机器位 |
| ADR-7 | SOP 编译为 LangGraph 图，版本锁定 | Runtime 总纲 §4.3；SOP 修改不影响进行中任务 | 编译产物按 `(sopId, version)` 缓存 |
| ADR-8 | LLM 配置 **org 级**（默认路由 + 档位覆盖） | Runtime §10.3 决议；不提供节点级配置 | 供应商切换以 ChatModel 适配层屏蔽 |
| ADR-9 | 时间一律 **UTC 存储**，业务语义按 `org.timezone` 解释 | 14 §7.2 / 07 §7 决议；`next_run_at` / `scheduled_at` 单一写入口 | 时区换算集中在调度层工具函数 |
| ADR-10 | 货币金额 `numeric` ↔ 字符串序列化 | 接口「字符串十进制金额」约定；杜绝浮点误差 | 序列化层统一转换（[02 §7](./02-数据访问层设计.md)） |

## 7. 非功能目标（MVP 基线）

| 维度 | 目标 | 落点 |
|---|---|---|
| API 性能 | 读接口 p95 < 300ms（不含 AI） | 索引策略 + 连接池（[02](./02-数据访问层设计.md)） |
| 实时性 | 任务事件 SSE 端到端 < 2s | Pub/Sub 直推（[04 §6](./04-任务调度与队列.md)） |
| 可用性 | api/worker 无状态可扩容，PG/Redis 托管 | [09 §2](./09-部署运维与可观测性.md) |
| 数据安全 | 凭据加密、RLS 双保险、审计四表串联 | [08](./08-安全设计与合规.md) |
| 成本可控 | LLM token/成本全量记账、预算告警不熔断 | [05 §6](./05-AgentRuntime与LLM网关.md) |
| 可追溯 | 每任务 steps/logs/outputs/审批全链路 | Runtime 总纲 §7 审计策略 |
