## 1. 环境矩阵

| 环境 | 用途 | 数据 | 基础设施 |
|---|---|---|---|
| dev | 本地开发 | 种子/工厂测试数据 | docker compose：pg16+pgvector / redis7 / minio / mailhog |
| staging | 预发验证 | 脱敏或造数 | 与 prod 同构（缩小规格） |
| prod | 生产 | 真实 | PG/Redis 托管云服务 |

- 配置差异全部经环境变量（清单 §4）；禁止代码内 env 分支判断（除日志级别）。

## 2. 生产拓扑

```text
                ┌─ LB/网关（TLS、SSE 透传、proxy_buffering off）
Internet ──────►│
                ├─► api ×2（无状态，HPA 2→6）
                │      ├── REST /api/v1
                │      └── SSE /tasks/{id}/stream（连接粘性非必需，经 Redis Pub/Sub）
                ├─► worker ×2（队列组可独立扩：q:lead_hunting 与 q:email_reply 分组）
                │
                ├─► PostgreSQL 16（托管，主+只读副本(P1)；pgvector/pg_trgm 扩展）
                ├─► Redis 7（托管，AOF；仅缓存/队列，可重建）
                └─► 对象存储（S3 兼容）
```

- **api 与 worker 分进程部署**（Runtime 总纲 §6）；worker 按队列分组扩容，`WORKER_INDEX` 分配雪花机器位（[02 §9](./02-数据访问层设计.md)）。
- 健康检查：`/healthz`（进程存活）、`/readyz`（DB/Redis 连通 + 迁移版本匹配）；K8s readiness/liveness 对应。
- 资源基线（MVP）：api 0.5C/512M、worker 1C/1G（Chromium 抓取节点单独 2G）、PG 2C/4G 起步。

## 5. CI/CD（GitHub Actions）

```text
PR 流水线：
  lint(turbo lint) → typecheck → unit/integration（Testcontainers）→ build
  → drizzle-kit check（schema/迁移一致性）→ 契约快照测试

main 合并 → 构建镜像（api / worker）→ 推送 registry
部署（staging 自动，prod 手动批准）：
  ① migrate Job：tradepilot_migrate 执行 drizzle-kit migrate（串行锁，失败即中止）
  ② 滚动更新 api（就绪探针通过再下一批）
  ③ 滚动更新 worker（先 drain：SIGTERM 等检查点落盘）
  ④ 冒烟：/readyz + 关键 E2E 只读用例
```

- 迁移纪律：只前滚不回滚（[02 §2](./02-数据访问层设计.md)）；`llm_call` 等 ER 增补表随迁移链交付并回写 ER 文档版本。

## 6. 可观测性

### 6.1 日志

- pino JSON → 采集（Loki/云日志服务）；以 `traceId` 串联 api→queue→worker→工具全链（job payload 携带 traceId）。
- 保留 30 天（热）+ 180 天（冷归档，安全日志）。

### 6.2 指标（Prometheus）

| 指标族 | 关键项 |
|---|---|
| HTTP | qps、p50/p95/p99（按路由）、错误率（4xx/5xx） |
| 队列 | 各队列深度、等待时长、失败数、stalled 数 |
| 任务 | 按 task_type 的时长分布、失败率、并发占用（running 数） |
| LLM | 调用数、token、cost_usd（org 维度）、降级次数、P95 延迟 |
| SSE | 活跃连接数、事件推送延迟 |
| 邮箱 | 同步成功率、断连数、发信成功/失败 |

### 6.3 追踪

- OpenTelemetry：HTTP 自动埋点 + BullMQ 处理器 span + pg 查询 span + LLM 调用 span（attributes：promptRef/model/scene）；采样 10%（错误 100%）。

### 6.4 告警（对接 IM/邮件）

| 条件 | 级别 |
|---|---|
| API 5xx > 1%（5min） / p95 > 1s（10min） | 高 |
| 队列积压 > 100 或最老任务等待 > 10min | 高 |
| 任务失败率 > 5%（按类型，1h 窗口） | 中 |
| mailbox 连续同步失败 ≥3 / status=error 数 > 0 | 中 |
| LLM 预算 80% / 100% | 中 / 高（均不熔断，16 FR-10） |
| 审批积压（pending > 20 或最老 > 24h） | 中 |
| Redis/PG 连接异常、迁移版本漂移 | 高 |

## 7. 备份与恢复

| 对象 | 策略 |
|---|---|
| PostgreSQL | 每日全量 + WAL 连续归档（PITR）；含 pgvector/checkpointer 数据；保留 30 天；季度恢复演练 |
| Redis | 可重建（队列由 DB 对账补偿：DelayedJobReconciler，[04 §3.1](./04-任务调度与队列.md)）；AOF 每 60s |
| 对象存储 | 版本化 + 跨区复制（按云厂商能力） |
| 密钥 | 密管侧快照 + 轮换流程（08 §2） |

- RPO ≤ 5min（WAL）、RTO ≤ 1h；恢复演练脚本入库 `docker/backup/`。

## 8. 运维手册要点（Runbook 索引）

| 场景 | 处置 |
|---|---|
| 僵尸任务堆积 | ZombieReaper 自动回收；批量重试走 `retry_of` 脚本（04 §5.4） |
| 邮箱大面积断连 | 检查供应商配额/OAuth；重连引导 + 同步补偿（last_synced_at 回拨） |
| LLM 供应商故障 | 降级链自动切换（05 §6.2）；必要时 env 切换供应商 |
| pgvector 检索劣化 | `ANALYZE` + ef_search 调参；异常时临时切关键词-only（07 §4.1 ②路） |
| 紧急停发（发信事故） | Feature 级开关：email_send 工具全局熔断 env（`OUTBOUND_EMAIL_DISABLED`）→ Gate 直接拒绝并入待审 |
| 数据订正 | 只走幂等脚本（packages/db/scripts），禁手工 UPDATE 生产 |
