## 3. 接口详细定义

### 3.1 GET /api/v1/tasks

请求参数：`status`、`employeeId`、`type`、`keyword`、分页。
响应 `data.items[]`：1.1 字段。示例：

```json
{ "taskId": "task_1001", "title": "寻找美国跑鞋品牌", "employeeId": "emp_1",
  "employeeName": "AI 获客员工", "role": "lead_hunter", "type": "lead_hunting",
  "status": "running", "progressPct": 80, "createdAt": "2026-09-04T14:30:00Z" }
```

### 3.2 POST /api/v1/tasks（通用新建）

请求：`{ employeeId, type, title, input }`
响应：`{ taskId, status: "running" | "scheduled" }`。
说明：业务化入口（如获客 `POST /lead-tasks`）内部落到此模型；`+ 新任务` 为统一入口，`type` 决定 SOP 与权限。

### 3.3 GET /api/v1/tasks/{id}/logs

请求参数：`after`（上一页最后 logId，增量拉取）、`limit`（默认 50）。
响应 `data`：`{ items: [ { logId, time, type, content, leadId? } ], hasMore }`。

### 3.4 GET /api/v1/tasks/{id}/stream（SSE）

事件流：

```text
event: log      data: { "logId": "...", "type": "match", "content": "产品匹配度：92%" }
event: progress data: { "progressPct": 80, "currentStep": "分析公司官网" }
event: status   data: { "status": "waiting_approval", "linkedApprovalId": "appr_30" }
event: done     data: { "status": "completed", "outputs": [...] }
```

### 3.5 POST /api/v1/tasks/{id}/retry

响应：`{ taskId, status: "running" }`（重试保留原 logs，新增 `retryOf` 标记）。

## 4. 联动与边界

- **执行链路**（§21 工作流）：Task → Agent Runtime（Planner/Memory/Tools）→ Workflow → AI SOP → 自动执行 / AI 建议 / 人工审核 → Result；`steps/logs/outputs` 支持全链路追溯与审计。
- `waiting_approval` 任务与 [12-AI审核中心](./12-AI审核中心.md) 联动，approve 后任务继续或完成。
- 任务调用外部工具的权限由 AI 员工 `permissions`（[02-AI数字员工中心](./02-AI数字员工中心.md)）约束，越权调用返回 `40301`。
- 并发排队、定时触发时区策略待澄清；`scheduled` 任务由调度器按时触发。
