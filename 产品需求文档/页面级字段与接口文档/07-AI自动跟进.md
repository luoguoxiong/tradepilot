## 1. 页面区块与字段清单

### 1.1 跟进任务总览（FR-01）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| executingCount | number | ✓ | 「正在执行：N 个跟进任务」 |
| tabs | — | ✓ | `all / today / waiting_approval / completed`（各档数量） |

### 1.2 跟进任务列表（FR-02）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| followUpTaskId | string | ✓ | 任务 ID |
| customerId / companyName | string | ✓ | 客户（跳转 360°） |
| currentStage | string | ✓ | `follow_up_1 / follow_up_2 / follow_up_3 / quote_followup` |
| nextRunAt | string | ✓ | 下次跟进时间（Today / Tomorrow / Sep 10） |
| status | string | ✓ | followUpTaskStatus：`ready` 🟢 / `scheduled` 🟢🔵 / `waiting_approval` 🟡 / `completed` ✓ / `paused` |
| strategyId / strategyName | string | ✓ | 所属策略 |

### 1.3 跟进策略时间线（FR-03）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| strategyId / name | string | ✓ | 策略 |
| steps[] | object[] | ✓ | `{ day: 0, title: "Initial Email", templateId, status: done ✓ | running ⏳ | pending ○ }` |
| 默认策略 | — | — | Day 0 Initial Email → Day 3 Product Value → Day 7 Product Case → Day 14 Customer Case → Day 30 Break-up Email |

### 1.4 新建/编辑策略表单（FR-04）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | ✓ | 策略名 |
| targetScope | object | ✓ | 适用范围：`{ customerValue: [high, medium], industry?: [], tags?: [] }` |
| steps[] | object[] | ✓ | `[{ dayOffset, templateId | content, channel: "email" }]` |
| autoSendPolicy | string | ✓ | `manual_review` 全部人工审核 / `auto_send` 自动发送 / `value_based` 按客户价值分级（高价值强制人工审核） |
| enabled | boolean | ✓ | 启用状态 |

### 1.5 执行记录（FR-05）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| executionId | string | ✓ | 执行 ID |
| stepTitle / sentAt | string | ✓ | 步骤 / 时间 |
| status | string | ✓ | `sent / waiting_approval / approved / rejected / failed / skipped（skipReason: customer_replied 客户回复自动暂停 \| frequency_capped 频控顺延留痕）` |
| content / approvedBy | string | — | 实际内容 / 审批人 |

## 2. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/follow-ups/summary` | 总览统计（executingCount + 各 Tab 数量） |
| GET | `/api/v1/follow-up-tasks` | 跟进任务列表 |
| GET | `/api/v1/follow-up-strategies` | 策略列表 |
| POST | `/api/v1/follow-up-strategies` | 新建策略 |
| PUT | `/api/v1/follow-up-strategies/{id}` | 编辑策略 |
| GET | `/api/v1/follow-up-strategies/{id}/executions` | 执行记录 |
| POST | `/api/v1/follow-up-tasks/{id}/pause` | 暂停单个客户跟进（如客户已回复） |
| POST | `/api/v1/follow-up-tasks/{id}/skip` | 跳过下一步 |
| POST | `/api/v1/follow-up-strategies/{id}/apply` | 应用策略到客户（单选/批量，见 §3.5） |

> 审批联动：`waiting_approval` 的跟进发送统一生成 `approvalType = email_send` 的审批项，处置接口见 [12-AI审核中心](./12-AI审核中心.md)；本模块不单独提供 approve 接口。**审批超时级联（v0.3，对齐 Runtime §4.7）**：审批 `expired` → 关联 `ai_task.status='failed'（approval_expired）`、`follow_up_task.status='paused'` 转人工（可在本模块手动发送或重新启用策略）；挂起期间 `next_run_at` 冻结原值、Scheduler 不扫描。

## 3. 接口详细定义

### 3.1 GET /api/v1/follow-ups/summary

响应 `data`：

```json
{ "executingCount": 42, "tabs": { "all": 42, "today": 6, "waitingApproval": 3, "completed": 120 } }
```

### 3.2 GET /api/v1/follow-up-tasks

请求参数：`tab(all|today|waiting_approval|completed)`、`keyword`、分页。

响应 `data.items[]`：

```json
{ "followUpTaskId": "ftask_5", "customerId": "cus_3", "companyName": "Fit Brand",
  "currentStage": "quote_followup", "nextRunAt": "2026-09-10T09:00:00Z",
  "status": "waiting_approval", "strategyId": "strat_1", "strategyName": "默认跟进策略" }
```

### 3.3 POST /api/v1/follow-up-strategies

请求体：1.4 表单字段。响应：`{ strategyId }`。

校验：
- Break-up Email（`templateType = breakup`）节点 `autoSendPolicy` 强制为 `manual_review`（需求文档 §4）；
- `dayOffset` 递增校验，重复天数返回 `42201`。

### 3.4 GET /api/v1/follow-up-strategies/{id}/executions

响应 `data.items[]`：1.5 字段；`skipped` 的记录带 `skipReason`：`customer_replied`（客户回复自动暂停）/ `frequency_capped`（频控顺延留痕）。

### 3.5 POST /api/v1/follow-up-strategies/{id}/apply

请求：`{ customerIds: ["cus_1", "cus_2"] }`。响应：`{ created: [{ customerId, followUpTaskId }], skipped: [{ customerId, reason: "task_exists" }] }`。

校验：客户无进行中（非 `completed`/`paused`）跟进任务才创建（**每客户仅 1 个进行中任务**，需求 §7）；`next_run_at` 首步按 `day_offset` 与企业发送时间窗计算（见 §4）。

## 4. 联动与边界

- **客户回复自动暂停**：收件箱（06）识别到客户回复后，系统自动 `pause` 该客户进行中的跟进任务并写 `skipped` 记录（避免机器邮件与人工沟通撞车）。
- **发送受控**：`auto_send` 策略下发送仍由服务端按频控规则限流：`org.send_rules.minTouchIntervalDays`（默认 3 天，同一客户任意 outbound 邮件最小间隔，含人工发送）；**Scheduler 入队前预检**，不满足则顺延 `next_run_at` 并写 `skipped(frequency_capped)`（配置见 [16-系统设置](./16-系统设置.md) FR-12）。顺延目标公式（v0.2.1，需求 §7.3）：`max(当前 next_run_at, 最近一次 outbound 时间 L + minTouchIntervalDays 天)` 后按 `org.timezone` 窗口对齐（< 09:00 → 当日起点，≥ 18:00 → 次日起点，窗口内保持），保证落点必在窗口内、到期即可入队。
- **内容约束**：跟进内容模板来自 [11-知识中心](./11-知识中心.md)；禁止编造优惠/交期/价格承诺（模板变量校验）。
- 跟进结果回写 [05-CRM客户中心](./05-CRM客户中心.md) 活动时间线。
- 时区与时间窗（需求 §7 已澄清）：触发按**企业当地时间**（`org.timezone`）+ 发送时间窗（`send_rules.sendWindow`，默认 09:00–18:00）；到期落在窗口外顺延至下一窗口起点；「今天待执行」= 企业当地日历日；`next_run_at` 统一存 UTC，展示/触发按企业时区换算。
