## 1. 模块定位

### 1.1 页面目标

统一管理所有 AI 员工的任务：任务创建、执行状态、进度、审批与失败重试，是 Agent Runtime 任务层的用户界面。

### 1.2 任务状态语义

```text
🟢 Running           # 执行中
🟡 Waiting Approval  # 等待审核
🔵 Scheduled         # 已排期
✓ Completed          # 已完成
🔴 Failed            # 失败（需重试/人工介入）
```

## 3. 功能需求

| 编号  | 需求            | 说明                                                                                           |
| ----- | --------------- | ---------------------------------------------------------------------------------------------- |
| FR-01 | 状态 Tab        | 全部 / Running / Waiting Approval / Completed / Failed（**P1**；P0 简化版为无 Tab 的任务列表） |
| FR-02 | 任务列表        | 字段：任务名、所属 AI 员工、状态、进度百分比                                                   |
| FR-03 | 新建任务        | 「+ 新任务」跨员工统一下发任务入口（或跳转对应员工工作台）                                     |
| FR-04 | 任务详情        | 查看任务执行日志（联动各员工工作台的实时日志）、执行步骤、产出结果                             |
| FR-05 | 审批联动        | Waiting Approval 任务联动 AI 审核中心                                                          |
| FR-06 | 失败处理        | Failed 任务支持查看失败原因、重试、转人工                                                      |
| FR-07 | 任务取消 / 暂停 | 支持暂停执行中的任务（如获客工作台的 ⏸ 暂停）（**P1**，完整版；P0 仅 retry 与审批联动）        |

---

## 4. AI 行为边界

- 任务执行遵循 §21 工作流：Agent Runtime（Planner / Memory / Tools）→ Workflow → 执行 AI SOP → 自动执行 / AI 建议 / 人工审核 → Result。
- 每个任务必须记录执行日志与产出物，支持追溯与审计。
- 任务调用外部工具（搜索、邮件等）的权限由 AI 员工配置（Permissions）约束。

## 6. 效果指标（建议）

- 任务完成率与失败率；失败后自动重试成功率。
- Waiting Approval 任务的审批时效。
- 任务平均执行时长（按任务类型）。
