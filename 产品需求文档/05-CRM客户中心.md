## 1. 模块定位

### 1.1 页面目标

统一沉淀企业的客户资产：潜在客户、正式客户、联系人与全部活动，支撑 AI 与人工的协同管理（阶段推进、下一步动作）。

### 1.2 目标用户

- 一线业务员：管理自己负责的客户
- 外贸经理：查看团队客户资产（负责人维度）

## 3. 功能需求

| 编号  | 需求         | 说明                                                                                                                                                       |
| ----- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-01 | 四类页签     | 潜在客户 / 正式客户 / 联系人 / 全部活动                                                                                                                    |
| FR-02 | 搜索与筛选   | 关键词搜索 + 国家 / 状态 / 负责人筛选                                                                                                                      |

---

## 4. AI 行为边界

- 「AI 建议重新激活」仅为建议，不自动发送任何邮件。
- 客户阶段由人工或明确的业务规则推进；AI 不得擅自变更客户阶段。
- 客户删除 / 合并为高危操作，必须经 AI 审核中心人工批准。

## 6. 效果指标（建议）

- 客户阶段推进率（New Lead → Contacted → Negotiation 的流转效率）。
- Cold 客户重新激活率。
- 客户资料完整度（联系人、阶段、下一步均有值的客户占比）。

## 7. 待澄清问题

1. ~~「潜在客户」与「正式客户」的判定规则（首次成交自动升级？）~~ → **已澄清**（v0.2）：
   - 潜在/正式为**客户身份**（potential / formal），与 `stage` 跟进阶段解耦，互不影响。
   - **首次成交自动升级**：客户名下报价被标记成交（[09-报价中心](./09-报价中心.md) `mark-won`，人工动作）时，若客户为潜在客户则自动升级为正式客户，写入活动流水，且不自动降级；属明确业务规则，AI 不得变更客户身份（§4）。
   - **MVP（P0）处理**：09/10 均为 P1、MVP 无成交信号源，添加客户默认潜在，负责人可在添加/编辑客户时手工归属；自动升级随报价中心（P1）启用。
2. ~~负责人分配机制：AI 发现的客户默认负责人是谁，如何转交。~~ → **已澄清**（v0.3）：
   - **默认负责人 = 触发「加入 CRM」的操作人**：AI 获客产出的 lead 为 org 级共享池（无个人归属，见 [03-AI获客](./03-AI获客.md)），`add-to-crm` 由人工触发，新建客户的 `ownerId` 默认取当前登录用户（与手工添加口径一致，FR-03）。
   - **经理指派**：`add-to-crm` 支持可选 `ownerId`，仅经理/管理员可指定他人（业务员传入他人 id 返回 `40301`）；命中已有客户（`mapped`）时不改归属。
   - **转交**：仅经理/管理员可通过编辑客户修改 `ownerId`，转交写 `owner_change` 活动流水，数据权限随新负责人即时切换；业务员不可私自转出/转入；AI 不得变更归属。
   - 不引入公海池：`owner_id NOT NULL` 保证总有归属，经理改派兜底。
3. ~~潜在客户 / 联系人 / 活动页签的字段清单与批量操作。~~ → **已澄清**（v0.4）：
   - **字段清单**：三个页签以[接口文档 §1.1/§1.3](./页面级字段与接口文档/05-CRM客户中心.md) 为准；活动行补 `refType/refId`（对齐客户 360° Activities 跳转与 ER `ref_type/ref_id`），联系人行补 `isPrimary`（主联系人标识，对齐 ER）。
   - **批量操作（仅客户页签，FR-08）**：多选批量删除——逐客户生成 `customer_delete` 审批并进入删除待审锁定态（高危边界对齐 [12-AI审核中心](./12-AI审核中心.md)）；批量改派负责人——仅经理/管理员，逐客户写 `owner_change`（口径见问题 2）；批量身份切换（转正式/潜在）与批量导出 v0.1 不做。
   - **联系人页签**：支持单条删除（普通写操作，不走审批、不写客户活动，与新增/编辑一致）；不做批量操作。
   - **活动页签**：只读时间线，无批量操作。
