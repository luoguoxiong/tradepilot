## 1. 性能预算与指标

| 指标 | 目标（1440px 桌面，生产构建） |
|---|---|
| 首屏 JS（gzip，登录后 Dashboard） | ≤ 300KB |
| 全站最大单 chunk | ≤ 500KB |
| LCP（staging 实测，P75） | ≤ 2.5s |
| INP | ≤ 200ms |
| 路由切换（已缓存） | ≤ 100ms（keep-alive） |

以 web-vitals 实测上报为准（[05 §5](./05-权限与安全设计.md)），CI 构建体积超预算即失败（`bundlesize` 门禁）。

## 2. 加载与分包

| 手段 | 落点 |
|---|---|
| 路由级懒加载 | 全部 views `() => import()`；P1 模块整目录独立 chunk，P0 构建期被 `features.ts` tree-shake 后不入包 |
| vendor 分包 | element-plus / echarts / tiptap 各自独立 chunk（[01 §5.2](./01-工程架构与规范.md)） |
| ECharts 按需注册 | 仅注册用到的图型/组件（BarChart/LineChart/PieChart/RadarChart/FunnelChart + 必要 renderer），避免全量 1MB |
| 组件库样式 | Element Plus 按需自动导入（unplugin-vue-components + unplugin-auto-import） |
| 图片懒加载 | 产品图/头像 `loading="lazy"` + 尺寸占位防 CLS |
| 预加载 | 登录成功后 `prefetch` Dashboard chunk；Sider 悬停 prefetch 对应模块 |

## 3. 运行时性能

| 手段 | 落点 |
|---|---|
| 虚拟滚动 | 会话消息 / 任务日志流（`StreamLogPanel`）/ 大表格（>100 行）；阈值见 [04 §4](./04-核心交互与组件设计.md) |
| keep-alive | 高频列表页（[02 §6](./02-路由与页面架构.md)）；最多缓存 8 个实例（LRU 由 include 控制） |
| 请求合并与缓存 | vue-query：列表页返回不重复请求（staleTime [03 §5.2](./03-状态管理与数据请求.md)）；`keepPreviousData` 防筛选切换闪烁 |
| 轮询收敛 | 全局轮询管理器：页面隐藏（`document.hidden`）暂停所有 refetchInterval 与 SSE，恢复可见统一恢复（配合 visibilitychange） |
| SSE 生命周期 | 单任务单连接，路由离开 abort；禁止多处同时订阅同一 taskId（`useTaskStream` 内部按 taskId 共享连接） |
| 防抖节流 | 搜索 300ms；窗口 resize 100ms；scope/筛选变更用 URL query 驱动，天然合并 |
| 长列表交互 | CRM/发现列表行内操作采用局部更新（乐观更新），不整表 refetch |

## 4. 感知性能

- 骨架屏：Dashboard 卡片、列表页、详情页三套统一骨架组件；
- 转场：路由切换 150ms fade；抽屉/弹窗使用 Element 默认动效（不额外引入动效库）；
- 乐观反馈：审批处置、加入 CRM 等操作即时变更 UI（失败回滚，[03 §5.3](./03-状态管理与数据请求.md)）；
- 弱网：SSE 断线降级轮询有续传语义（[03 §6.2](./03-状态管理与数据请求.md)），日志不丢不重。

## 5. 测试策略

### 5.1 分层

| 层 | 工具 | 范围与门槛 |
|---|---|---|
| 单元 | Vitest | `utils/`（format/enum-map/decimal 金额）、`stores/`、`composables/`（重点 `useTaskStream` 事件归并/去重/重连降级）、`api/` 错误码管道。diff 覆盖率：utils/composables ≥ 90% |
| 组件 | Vitest + @vue/test-utils | `business/` 核心组件：InsightCard（schema 渲染/低置信态/已删引用）、ApprovalCard（三态/超时态）、ProTable（分页筛选联动）、DraftEditor（insert_draft/消毒） |
| 契约 | 类型 + MSW | `api/types` 与接口文档对齐由 TS 编译期保证；MSW handler 以接口文档 schema 为源，契约漂移即测试红 |
| E2E | Playwright | 主流程（§5.2）；staging 每日回归 + 发布前必跑 |

### 5.2 E2E 主流程用例（对齐 [PRD §6 用户主流程](../产品需求文档/00-产品总览与MVP规划.md)）

1. 登录 → 企业初始化向导（上传资料 → 连接邮箱 → 完成）断点续走；
2. 获客：创建任务 → 日志流出现 → done → 发现列表 → 批量加入 CRM；
3. 销售：收件箱打开会话 → insert_draft 生成草稿 → 发送 → 出现待审（approvalRequired）；
4. 审批：审核中心对应 Tab → 编辑后批准 → 任务状态联动；
5. CRM：列表筛选/scope 切换/批量改派（manager）；
6. 权限：sales 登录验证菜单与操作裁剪、越权 URL 返回无权限态。

### 5.3 Mock 体系

- MSW 2.x，handler 按[页面级字段与接口文档](../产品需求文档/页面级字段与接口文档/00-总览与接口规范.md)逐份实现，含分页/错误码/SSE 模拟（`ReadableStream` 推送 log/progress/status/done 事件）；
- dev 环境可切 `VITE_USE_MOCK=true` 独立开发（后端未就绪的模块先行开发）；
- MSW handler 与单测复用，保证「mock 即契约」。

### 5.4 CI 质量门禁

```text
lint → type-check(vue-tsc) → unit/component → build → bundle 体积门禁 → (staging) e2e
```

- 任一环节红即阻塞合入；`features.ts` 变更需附 e2e 对应 profile 的运行结果。
