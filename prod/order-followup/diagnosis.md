# AI 外贸跟单助理（order-followup）诊断报告

- 版本：v1
- 日期：2026-09-04
- 诊断对象：用户一句话需求（8 项功能：读取订单/PI/进度跟踪/交期提醒/催货/装箱单+Invoice/进度邮件/异常整理）
- 项目背景：tradepilot 二期；一期 customer-prospecting 已上线（Fastify+SQLite+DeepSeek / Vue3）

## 一、产品定位复盘

- 原始定位陈述：自动读取客户订单、生成单证、跟踪进度、提醒催货、发邮件、整理异常。
- 重新校准后定位（一句话）：为【外贸一线业务员/SOHO】在【订单履约全周期】下解决【订单信息散落、单证手工制作、交期靠脑子记、催货不及时】的问题，相比【Excel台账+手工单证+记忆提醒】实现【订单录入 15分钟→2分钟、单证制作 30分钟→1分钟、提醒零遗漏】的效率提升。

## 二、五维诊断评分

| 维度 | 得分 | 关键发现 |
|------|------|---------|
| 业务价值 | 5/5 | 跟单占外贸人约 20% 时间，高频刚需；逾期/漏催直接造成钱货损失，价值可量化 |
| AI适配度 | 3/5 | 订单解析（非结构化→结构化）、邮件生成是 AI 强项；但单证金额绝不可纯 LLM 生成，需架构约束（模板+校验） |
| 用户体验 | 3/5 | 8 项功能若平铺会很重；必须以「订单」为中心组织，异常聚合一屏可见；用户已确认单账号单业务员视角，可控 |
| 数据与集成 | 3/5 | 订单来源已定（文件上传+AI解析），无 ERP/物流 API；邮件发送需用户自备 SMTP；工厂交期靠人工更新+系统提醒，无硬数据依赖，风险可控 |
| 成本与商业化 | 4/5 | LLM 调用低频（每订单解析 1 次、邮件/单证按需），Token 成本低；一期已沉淀 LLM client（JSON 模式+重试+降级），边际开发成本低 |

## 三、核心问题清单（按优先级）

### P0（正确性/生死线）
1. **单证数字错误风险**：PI/Invoice/PL 的金额、数量、单价、币种、贸易术语若由 LLM 自由生成，出错=清关延误/罚款/丢单。→ 必须采用「模板引擎填充 + 结构化字段 + 校验器 + 人工确认」架构。
2. **解析结果未确认直接入库**：上传订单 AI 解析必有错漏（尤其 PDF 扫描件/邮件格式混乱）。→ 解析结果必须经人工确认后才能建单。
3. **未经确认的自动外发邮件**：已确认 v1 采用「生成+确认+SMTP 发送」，杜绝 AI 直接对外发送。

### P1（体验/留存）
4. **8 项功能的信息架构**：用户提的是能力清单而非产品结构；若做成 8 个平级菜单必然难用。→ 以订单为中心：导入→台账→详情（节点+单证+邮件）→ 异常看板聚合。
5. **提醒的及时性依赖打开页面**：无定时调度能力，一期队列是请求触发。→ 引入轻量定时检查（服务启动后 interval 扫描），提醒落库+页面聚合，不做推送。

### P2（增值/增长）
6. 多币种/汇率：v1 仅记录币种与金额，不做汇兑损益核算。
7. 邮件往来自动提取进度：用户已明确放二期之后（先手动更新+系统提醒）。

## 四、打磨方案（已落到 PRD v1）

### 问题1：功能多而散
- 现状与影响：8 项能力平铺，业务员学习成本高。
- 根因分析：需求以功能视角而非用户旅程视角描述。
- 改进方案：按订单生命周期重排 IA（详见 PRD §4 人机协同流程）；异常订单独立看板作为每日入口。
- 验证指标：新用户 5 分钟内完成首单导入并生成 PI。

### 问题2：单证正确性
- 现状与影响：纯 LLM 生成单证不可接受。
- 根因分析：需求未区分「AI 生成」与「确定性渲染」。
- 改进方案：单证 = 结构化字段（来自确认后的订单）+ HTML 模板引擎渲染 + 一致性校验器（大小写金额、数量×单价=总额、买卖双方信息、唛头）+ 人工确认。
- 验证指标：单证关键字段 100% 可溯源到订单字段；校验器拦截率统计。

### 问题3：邮件发送能力缺失
- 现状与影响：一期只有 .eml 导出，无 SMTP。
- 改进方案：新增 SMTP 配置（设置页，密码本地加密存储），邮件「AI 生成草稿 → 人工编辑 → 确认发送」，发送记录落库。
- 验证指标：邮件采纳率（发送前修改幅度）>80%；发送成功率。

## 五、边界说明（诚实边界）

- AI 做不到：保证扫描版 PDF 解析成功率（图片型 PDF v1 明确不支持，提示转手动录入）；自动跟踪工厂生产实况（无数据源）；预测汇率。
- v1 明确不做：邮箱 IMAP 自动拉单、物流轨迹对接、多用户权限、报关单证（报关单/原产地证）。
