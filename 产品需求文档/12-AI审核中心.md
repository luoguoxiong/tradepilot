## 1. 模块定位

### 1.1 核心原则

**AI 的高风险行为必须进入 Human-in-the-Loop**：AI 可以建议、起草、执行低风险动作，但所有高风险动作必须经人工批准后生效。

### 1.2 审核类型（源文档明确列出）

| 审核类型 | 风险说明 |
|---|---|
| 报价 | 价格具有法律效力，直接影响利润与履约 |
| 邮件发送 | 对外沟通，错误内容损害客户关系 |
| 合同 | 法律文件 |
| 订单变更 | 影响交期、金额、履约 |
| 批量营销 | 规模化外发，错误会被放大 |
| 客户删除 | 不可逆的数据资产损失 |

## 3. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-01 | 分类待办 Tab | 全部 / 报价 / 邮件 / 订单 等，各 Tab 显示待审数量；支持按其余审核类型（合同 / 批量营销 / 客户删除）扩展 |
| FR-02 | 审核卡片 | 展示审核类型与风险等级（High Risk）、业务上下文（客户、产品、数量）、AI 建议（如价格）、**Confidence 置信度**、**AI 原因（逐条证据）** |
| FR-03 | 三态处置 | [拒绝]（驳回并记录原因）/ [编辑]（修改后批准，需留痕修改前后差异）/ [✓ 批准]（放行执行） |
| FR-04 | 审核留痕 | 全部审核记录可追溯：谁、何时、对什么、做了什么决定、是否编辑过内容 |
| FR-05 | 超时策略 | 超时时间 `expiresAt` 按类型默认时效（16 可配，默认 48h）；超时未处理 → 邮件提醒经理一次（多级升级列后续，见 §7） |
| FR-06 | 权限 | 审批权限与业务角色绑定（如报价审核需经理以上），见 16-系统设置权限管理 |

## 4. AI 行为边界

- 本模块是 AI 权限的「闸门」：**未经批准的高风险动作一律不得执行**。
- Confidence 与 AI 原因必须真实反映模型置信依据，禁止虚构置信度。
- 审核拒绝不是终点：拒绝原因应回流给对应 AI 员工作为反馈（形成「AI 生成 → 人工确认 → 修正反馈」闭环）。

## 6. 效果指标（建议）

- 审核时效：待审项平均处理时长、超时率。
- AI 建议直批率：不经编辑直接批准的比例（衡量 AI 质量）。
- 高危拦截价值：被拒绝的高风险动作数及避免的损失事件。
