## 3. 接口详细定义

### 3.1 POST /api/v1/knowledge/documents

请求：`multipart/form-data`：`file` + `category` + `source`（可选：`upload / email_attachment`，默认 `upload`；`product` 仅由 08 归档内部写入）。
响应：`{ docId, status: "indexing" }` —— 索引异步执行，前端轮询列表或订阅状态。
校验：格式白名单（pdf/docx/md/txt）与大小上限（**50MB**，需求 §7 已确认），超限 `42201`。

### 3.2 POST /api/v1/knowledge/documents/{id}/retry

响应：`{ status: "indexing" }`；连续失败需明确提示（不允许静默丢失知识）。

### 3.3 POST /api/v1/knowledge/search

请求：

```json
{ "query": "Carbon Fiber Insole 的 MOQ 和优势", "category": ["product"], "topK": 5,
  "scene": "sales_reply" }
```

`scene` 枚举：`lead_match`（获客匹配）/ `sales_reply`（销售回复）/ `follow_up`（跟进内容）/ `pricing_basis`（报价依据）/ `business_analysis`（经营分析）。

响应 `data`：

```json
{ "results": [
  { "docId": "doc_3", "docName": "Carbon Fiber Catalog.pdf", "chunkId": "chk_12",
    "content": "MOQ 500 pairs, lead time 25 days…", "score": 0.91, "category": "product" } ],
  "noResult": false }
```

`noResult = true` 时调用方必须向用户明确提示「知识库中没有相关信息」，禁止编造。

### 3.4 DELETE /api/v1/knowledge/documents/{id}

权限：仅经理 / 管理员（业务员返回 `40301`）。响应：`{ deleted: true }`；**软删留痕（v0.2.1，需求 §7.2）**：置 `deleted_at / deleted_by`，文档行保留（报价 / 草稿 / 审批 outputs 中的 docId 引用仍可回溯，展示标记「已删除」），分块与向量随删动物理清除——检索与列表强制过滤已删文档，实时同步失效引用该文档的缓存与产品知识条目（检索直查向量库、无长缓存，失效即生效）。

## 4. 联动与边界

- **知识库是 AI 事实的唯一来源**：所有 AI 产出（06 草稿、03 匹配、09 报价依据、13 经营分析）引用必须可回溯 `docId/chunkId`。
- 产品资料（08 Documents）自动归档为 `category=product` 文档。
- 权限（需求 §7 已澄清）：检索 / 引用 **org 级全量共享**（AI 员工需全量知识才能有据可依），不按角色过滤；上传 = 全员；删除 / 重试 = 仅经理与管理员（`40301`）；敏感分类列后续增强。
- **覆盖式更新（需求 §7 已澄清）**：不做多版本共存，更新 = 软删旧文档（留痕，见 §3.4）+ 上传新文档；邮件附件入库走本接口（`source='email_attachment'`，06 会话详情入口）；网页抓取入库列后续增强。
