## 2. 邮箱集成（P0，MVP 主流程依赖）

### 2.1 Driver 接口

```typescript
interface MailboxDriver {
  testConnection(): Promise<{ imap?: 'ok'|'fail'; smtp?: 'ok'|'fail' }>;
  syncMessages(params: { since: Date; folders: string[] }): AsyncIterable<RawMessage>;
  sendMessage(msg: OutboundMessage): Promise<{ externalId: string }>;
  markSeen?(externalId: string): Promise<void>;
}
```

| Provider | 收 | 发 | 增量机制 | 备注 |
|---|---|---|---|---|
| gmail | Gmail API（googleapis） | Gmail API | `historyId` 增量拉取 | OAuth2（refresh token 存凭据） |
| outlook | Microsoft Graph | Graph sendMail | delta 查询 | OAuth2（device code / auth code） |
| smtp_imap | imapflow（IMAP IDLE 优先，轮询兜底） | nodemailer | UID + `since` | 16 §2.6 表单：host/port/SSL 凭据 |

- 连接测试：IMAP / SMTP 分别校验并回显（16 §2.6）；保存前必须通过。
- 同步范围：`syncScope { historyDays, folders(INBOX/Sent) }` 首次全量回填，此后增量。

### 2.2 收信链路（q:email_sync）

```text
MailboxSyncScheduler（每 5min）或 IMAP IDLE 推送
→ driver.syncMessages(since=last_synced_at)
→ 逐消息幂等入库（单事务，02 §5）：
   external_message_id（Message-ID）唯一冲突 → 跳过
   conversation upsert（customer+contact 匹配，未匹配则新建轻量线索会话）
   message 插入（direction='in'，language 检测留空由 email_reply 图判定）
   → 新客户来信：conversation.unread_count+1、priority 评估
   → 自动 pause 该客户进行中 follow_up_task + 写 follow_up_execution(skipped)（07 §4）
   → 若属销售域询盘类 → 创建 ai_task(email_reply) 入队（排队语义同 14 §3.2）
→ 更新 mailbox.last_synced_at；连续失败 ≥3 次 → status='error' + 通知
```

- 附件：转存对象存储，`message.attachments` 记 key 列表；「存入知识库」接口复用存储 key 直接转 knowledge_document（`source='email_attachment'`，11 FR-07）。

### 2.3 发信链路（唯一出口）

- 工具 `email_send` → 审批放行后 → driver.sendMessage → `message(direction='out', status='sent', external_message_id)` → CRM 活动记录 + 首响时长指标。
- 失败重试 2 次（指数退避）；最终失败 `message.status='failed'` + 任务日志 error + 通知。
- 系统通知邮件（邀请、审批提醒，FR-09）：复用 org 任一 `connected` mailbox 发送；无可用邮箱 → 仅站内通知。

### 2.4 凭据安全

- `credential_enc`：AES-256-GCM，主密钥 `ENCRYPTION_KEY`（env/密管），每行独立 IV；解密仅在发送/同步瞬间内存中进行；接口永不回显明文，仅回显脱敏（`sales***@company.com`）。
- OAuth token 刷新失败 → `status='disconnected'` + 重连入口提示。

## 3. 搜索与抓取（P0 获客依赖）

### 3.1 供应商适配

| 能力 | MVP 供应商（可配 env 切换） | 说明 |
|---|---|---|
| `web_search` | Tavily（主）/ Serper（备） | 返回结果统一 `{ url, title, snippet }`；供应商差异收敛于适配器 |
| `site_crawl` | Playwright（无头 Chromium）+ 直接 fetch 兜底 | 抓产品/About 关键页；尊重 robots.txt；单站限速 1 req/2s、超时 15s、页面 ≤ 2MB、最多 5 页 |
| `lookup_contact` | 站内邮箱格式启发式 + 预留 Hunter 类 API | **仅公开商务渠道**（GDPR/CCPA 边界，03 §4）；预留供应商开关 |

### 3.2 额度令牌桶（外部调用日额度）

```text
key: quota:{orgId}:{employeeId}:{yyyy-MM-dd}   （Redis INCRBY，TTL 48h）
配额来源：ai_employee.externalCallDailyLimit（默认 200，03 §3.7）
计权：search×1 / crawl×2 / lookup×1
超限 → 任务转 paused（outputs 提示额度用尽）→ 次日重置后手动 resume
```

- 双层防滥用：此外员工级额度 + email_send 租户/员工令牌桶（[08 §5](./08-安全设计与合规.md)）。
- `excludeDomains` 在 dedup_check 硬过滤（图内），非额度层。

## 4. 嵌入服务

- 供应商：OpenAI 兼容 `/embeddings`（MVP `text-embedding-3-small`，1536 维 = ER 06 `vector(1536)`）；org 可配（ai_model_setting 扩展场景 `embedding`，P1 细化）。
- 批量：≤ 100 条/请求；失败重试 2 次 → 文档索引失败（可重试）。
- **换维度 = 换模型**：维度不一致时禁止混存，需全量重建索引（迁移脚本清空 chunks 重跑，[07 §5](./07-知识检索与RAG.md)）。

## 5. 开放 API 与 Webhook（P1，16 FR-11）

### 5.1 API Key

- 创建：生成 `tpk_{keyPrefix}{random}`，明文仅返回一次；`key_hash = sha256(key)` 唯一索引查找。
- 中间件：ApiKeyGuard（[03 §2.2](./03-认证授权与多租户.md)）→ scopes 校验（`customers:read` / `tasks:write`…）→ 限流（每 Key 60 req/min，`42901`）。
- 停用成员名下 Key 即时失效；`last_used_at` 记账。

### 5.2 出站 Webhook

| 项 | 设计 |
|---|---|
| 事件 | `task.completed / approval.pending / approval.decided / message.received / customer.created`（注册表可扩展） |
| 签名 | `X-TP-Signature: t={ts}, v1={HMAC-SHA256(secret_enc, t + '.' + body)}`；secret 密文存储 |
| 投递 | q.notify → POST JSON；超时 10s；重试 5 次指数退避（1m~2h）→ 死信标记 |
| 幂等 | 事件携带 `eventId`（雪花），接收方去重 |
