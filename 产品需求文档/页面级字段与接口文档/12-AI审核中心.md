# 12 · AI 审核中心 · 页面字段与接口

| 项 | 内容 |
|---|---|
| 对应需求文档 | [12-AI审核中心](../12-AI审核中心.md) |
| 版本 | v0.2（2026-09-05，风险分级/自动通过、通知渠道、编辑差异交互澄清，见 §1.2/§1.4/§4）<br>v0.1（2026-09-04） |
| 页面 | 待审列表（分类 Tab）、审核卡片、处置操作 |

> 本模块是 AI 权限的「闸门」：所有高风险动作（approvalType 见 [00-总览 §3.5](./00-总览与接口规范.md)）在此人工批准后生效。

## 1. 页面区块与字段清单

### 1.1 分类 Tab（FR-01）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| tabs | object[] | ✓ | `[{ type: "all" | "quote" | "email_send" | "order_change" | "contract" | "bulk_marketing" | "customer_delete", count }]` |

### 1.2 审核卡片（FR-02）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| approvalId | string | ✓ | 审批 ID |
| approvalType | string | ✓ | 审核类型枚举 |
| riskLevel | string | ✓ | `high`（quote/contract/customer_delete，永远人工审，不可配自动通过）/ `medium`（email_send/order_change/bulk_marketing，可配自动通过）/ `low`（低风险动作不进审批中心，仅分类保留） |
| title | string | ✓ | 如「报价审核」 |
| context | object | ✓ | 业务上下文，按类型差异化（见 1.3） |
| aiProposal | object | ✓ | AI 建议（如 `{ suggestedUnitPrice: "12.50" }` / `{ emailContent }` / `{ changes }`） |
| confidence | number | ✓ | 置信度进度条（0~1，禁止虚构） |
| reasons | object[] | ✓ | AI 原因逐条证据（Insight Schema） |
| createdAt / expiresAt | string | — | 发起时间 / 超时时间（按类型默认 48h，16 可配；超时邮件提醒经理一次） |
| status | string | ✓ | approvalStatus |

### 1.3 context 按审核类型的字段

| approvalType | context 字段 |
|---|---|
| `quote` | `{ customerId, customerName, productName, quantity, aiProposal.suggestedUnitPrice, profitMarginPct }` |
| `email_send` | `{ conversationId, customerId, contactName, subject, contentPreview }` |
| `order_change` | `{ orderNo, changes: [{ field, before, after }] }` |
| `customer_delete` | `{ customerId, customerName, relatedCounts: { quotes, orders } }` |
| `bulk_marketing` | `{ audienceSize, templatePreview }` |
| `contract` | `{ contractId, customerName, contentUrl }` |

### 1.4 处置操作（FR-03）

| 操作 | 说明 |
|---|---|
| [✓ 批准] | 放行执行，触发原业务动作 |
| [编辑] | 字段行内编辑（AI 建议值与用户值并排、修改字段高亮），保存后生成 `editedDiff` 留痕（统一字段级 before/after 差异表；长文本 v0.1 整体替换留痕，需求 §7 已澄清） |
| [拒绝] | 驳回，必填拒绝原因（回流给对应 AI 员工作为反馈） |

### 1.5 审核留痕（FR-04）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| logId / approvalId | string | ✓ | — |
| approverName / decidedAt | string | ✓ | 谁、何时 |
| action | string | ✓ | `approved / edited_approved / rejected` |
| editedDiff | object[] | — | `[{ field, before, after }]` 编辑留痕 |
| rejectReason | string | — | 拒绝原因 |

## 2. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/approvals/summary` | 各类型待审数量（Tab） |
| GET | `/api/v1/approvals` | 审批列表（type/status 筛选） |
| GET | `/api/v1/approvals/{id}` | 审批详情（卡片字段） |
| POST | `/api/v1/approvals/{id}/approve` | 批准（可带编辑后内容） |
| POST | `/api/v1/approvals/{id}/reject` | 拒绝（必填原因） |
| GET | `/api/v1/approvals/{id}/logs` | 留痕记录 |

## 3. 接口详细定义

### 3.1 GET /api/v1/approvals/summary

响应 `data`：

```json
{ "tabs": [ { "type": "all", "count": 8 }, { "type": "quote", "count": 3 },
            { "type": "email_send", "count": 4 }, { "type": "order_change", "count": 1 } ] }
```

### 3.2 GET /api/v1/approvals?type=quote&status=pending

响应 `data.items[]`：

```json
{ "approvalId": "appr_30", "approvalType": "quote", "riskLevel": "high",
  "title": "报价审核", "status": "pending",
  "context": { "customerId": "cus_1", "customerName": "ABC Sports",
               "productName": "Carbon Fiber Insoles", "quantity": 5000 },
  "aiProposal": { "suggestedUnitPrice": "12.50", "profitMarginPct": 32 },
  "confidence": 0.92,
  "reasons": [
    { "text": "数量大", "evidence": "5,000 pairs", "source": "pricing_engine" },
    { "text": "客户评分高", "evidence": "Score 92", "source": "crm" },
    { "text": "利润率符合公司规则", "evidence": "32% ≥ 红线 25%", "source": "pricing_rule" } ],
  "createdAt": "2026-09-04T14:50:00Z" }
```

### 3.3 POST /api/v1/approvals/{id}/approve

请求（二选一）：

```json
{ "action": "approve" }
{ "action": "edited_approved", "editedContent": { "aiProposal": { "suggestedUnitPrice": "12.80" } } }
```

响应：`{ approvalId, status, resultRef: { quoteId, status: "sent" } }` —— 服务端回调原业务动作（发送报价/发送邮件/应用订单变更/删除客户）。

### 3.4 POST /api/v1/approvals/{id}/reject

请求：`{ reason: "价格偏高，建议分档报价" }`（必填，缺失返回 `42201`）
响应：`{ approvalId, status: "rejected" }`；`reason` 写入对应 AI 员工反馈队列（形成修正闭环）。

## 4. 联动与边界

- **未经批准的高风险动作一律不得执行**：各业务接口（09 submit/send、10 变更、05 删除、06/07 发送）只产生 `appr_`，实际执行由 `approve` 回调完成。
- 权限：审批人按类型绑定业务角色（报价审核需经理以上），见 [16-系统设置](./16-系统设置.md) 审批规则配置。
- 超时提醒（需求 §7 已澄清）：`expiresAt` 按类型默认 48h（16 可配）；超时未处理邮件提醒经理一次；多级升级 / 代审列后续。
- 通知渠道（需求 §7 已澄清）：站内徽标（`GET /approvals/summary` 轮询）+ 邮件通知（16 FR-09）；IM webhook 列后续增强。
- 风险分级与自动通过（需求 §7 已澄清）：`high` 永远人工审；`medium` 可在 16 FR-08 配置 `autoApprove`，自动放行写 `auto_approved` 留痕（枚举已扩展）。
