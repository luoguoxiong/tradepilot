## 1. 模块定位

### 1.1 页面目标

以单一客户为中心，聚合基本信息、联系人、往来会话、报价、订单与 AI 洞察，形成完整的客户资产视图，并给出「下一步动作」建议。

### 1.2 页面结构

```text
客户详情
├── Overview
├── Contacts
├── Products
├── Conversations
├── Quotes
├── Orders
├── Activities
└── AI Insights
```

## 3. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-01 | 客户头部信息 | 公司名、客户评分（Score）、国家、官网、行业标签；操作区：加入 CRM / AI 分析 / 联系客户 / 更多 |
| FR-02 | 页签导航 | Overview / Contacts / Products / Conversations / Quotes / Orders / Activities / AI Insights |
| FR-03 | 客户信息（Overview） | 公司规模、成立时间、客户类型、主营产品 |
| FR-04 | 产品匹配 | 该客户与本公司产品的匹配度列表（进度条 + 百分比） |
| FR-05 | AI 客户洞察 | ① 采购概率（百分比）② **AI 判断原因（证据链，必须展示）** ③ 推荐下一步动作（如「联系采购负责人 →」，可点击执行） |
| FR-06 | 联系人卡片 | 姓名、职位、决策影响力（Decision Influence 进度条）；操作：查看详情、AI 生成开发信 |
| FR-07 | 往来数据聚合 | Conversations（沟通记录）、Quotes（历史报价）、Orders（历史订单）、Activities（活动时间线）各页签数据 |

### 3.1 页签字段清单与交互（v0.2 澄清 §7.1）

各页签均为**对应模块列表接口的客户维度过滤**（字段清单以[接口文档 04 §1.4/§1.5](./页面级字段与接口文档/04-客户360°.md)为准，不另建存储，ER 04 §4「360° 页签复用」）：

| 页签 | 数据源（`customer_id` 过滤） | 行点击交互 |
|---|---|---|
| Contacts | contact（本模块） | 「查看详情」侧滑抽屉展示完整信息；「AI 生成开发信」→ §3.3 流程 |
| Products | customer_insight（`insight_type='product_match'`）或 lead.overview | 跳转 [08-产品中心](./08-产品中心.md) 产品详情 |
| Conversations | 06 会话列表 | 跳转 [06-AI销售工作台](./06-AI销售工作台.md) 对应会话（未读徽标 `unreadCount`） |
| Quotes | 09 报价列表 | 跳转 [09-报价中心](./09-报价中心.md) 报价详情 |
| Orders | 10 订单列表 | 跳转 [10-订单中心](./10-订单中心.md) 订单详情 |
| Activities | customer_activity | 条目按 `ref_type + ref_id` 跳转对应业务详情（message / quote / sales_order / follow_up_execution / ai_task） |

**交互通则**：

- 页签切换**懒加载**：首次进入该页签才发起请求；列表标准分页。
- 空态引导：Quotes 空态提示「去 09 创建报价」、Conversations 空态提示「去 06 开始沟通」等。
- 数据权限：所有页签随客户 `owner_id` 的 scope 校验，与列表页一致。
- 未入库客户（`inCrm=false`，来自获客「查看 →」跳转）：仅 Overview / Contacts / Products 可见（数据来自 lead 的 overview / insight / 联系人），其余页签空态提示「加入 CRM 后开启」。

**P0 阶段降级注记（v0.3，对齐 [00 §5.1](./00-产品总览与MVP规划.md) 降级矩阵）**：

- **Quotes / Orders 页签（D6）**：依赖 09/10（P1）——P0 两页签**隐藏**；Activities 中 `ref_type=quote/sales_order` 条目天然无数据无需处理；「去 09 创建报价」空态引导不渲染。
- **Products 页签行点击（D7）**：跳转 08 产品详情依赖 08（P1）——P0 行点击**不跳转**，展开行内详情侧滑展示 insight/overview 数据；跳转随 08 启用。

### 3.2 决策影响力计算口径（v0.2 澄清 §7.2）

两级产出，**前端只读**（v0.2 不提供人工修改，与 03 §3.5 评分口径的「单一来源」原则一致）：

1. **规则基线**：获客工作流 `find_contact`（tool 节点）按职衔关键词**确定性映射**产出 0–100 分值，写入 `ai_lead_contact.decision_influence_pct`；加入 CRM 时随联系人复制到 `contact`。无 AI 判断、可复算，无需证据链。

| 档位 | 分值 | 职衔关键词（不区分大小写） |
|---|---|---|
| 采购决策层 | 90 | Director / VP / Head / Chief / CPO +（Purchasing / Sourcing / Procurement / Buying） |
| 采购执行层 | 75 | Purchasing / Sourcing / Procurement Manager、Buyer、Merchandiser |
| 影响层 | 40 | Engineer / R&D / Quality 等识别到但非采购职能 |

未命中关键词 → NULL，前端显示「—」（不猜测）。映射表随 `jobTitles` 白名单（03 §3.4）配套维护。

2. **AI 精化**：客户 360°「AI 分析」（`scope=full`）时 LLM 基于官网/知识证据重算，**必须输出 Insight Schema** `{ value, confidence, reasons[{ text, evidence, source }] }`（证据链红线，§4）。落库规则：`value` → `contact.decision_influence_pct`，`reasons` → `contact.decision_influence_reasons`（Tooltip 展示）；`confidence < 0.5` 时视为证据不足，保留规则基线值、不覆盖。

### 3.3 「AI 生成开发信」产出流程（v0.2 澄清 §7.3）

```text
联系人卡片「AI 生成开发信」 / AI 洞察 nextAction(generate_outreach)
      ↓ POST /contacts/{id}/generate-outreach（产出草稿，不直接发送）
该联系人无会话 → 自动创建 outbound 会话（返回 conversationId）
      ↓ 草稿落入 06-AI销售工作台（status=draft，进入该客户会话的 AI 草稿区）
用户 [编辑] / [重新生成] / [保存草稿] → 「发送 →」人工确认
      ↓ 按审核策略进入 12-AI审核中心（邮件发送审批）
通过 → 经邮箱通道（16 系统设置）外发；拒绝 → 回草稿
```

- **不经销售中心「开发信 / 邮件模板」库**：模板区为 [06 §7.1](./06-AI销售工作台.md) 待补充的独立需求，MVP 不涉及。
- 与 06 §4「AI 只起草，人决定发送」一致：AI 不直接发送任何对外触达。

## 4. AI 行为边界

- **采购概率与评分必须附证据链**：AI 判断原因需逐条列出（产品匹配、规模符合、存在 OEM 产品线等），纯推断结论需标注依据来源；无法支撑的结论不给。决策影响力的 AI 精化同此红线（§3.2）；证据不足（confidence < 0.5）不覆盖规则基线值。
- **推荐动作为建议而非自动执行**：「联系采购负责人」「AI 生成开发信」等动作由用户点击触发；对外触达类动作进入销售中心流程并接受审核中心约束。
- 「AI 分析」属于读取与推理操作，不修改客户数据；客户删除/合并等高危操作走审核中心。

## 6. 效果指标（建议）

- AI 洞察采纳率：用户点击「推荐下一步」的比例。
- 采购概率准确性：高概率客户的实际回复 / 成交率显著高于低概率客户。
- 客户 360° 访问频次（获客列表 → 详情的点击率）。
