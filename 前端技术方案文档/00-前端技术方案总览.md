## 1. 方案定位

本文档定义 TradePilot AI Web 前端的技术选型、工程架构、核心交互实现方案与工程规范，作为前端开发、代码评审与联调的统一依据。

设计基线：

- **形态**：PC 优先 SaaS 中后台，1440px 基准（[00-产品总览 §7](../产品需求文档/00-产品总览与MVP规划.md)：Sider 240px / Header 64px / 内容最大宽 1600px）；
- **交付策略**：P0 先行，P1 模块按[降级矩阵](../产品需求文档/00-产品总览与MVP规划.md)逐项恢复，**不做运行时功能开关 UI**（编译期特性常量控制，见 [02-路由与页面架构 §5](./02-路由与页面架构.md)）;
- **产品原则对齐**：非 Chat 形态——前端围绕「任务 → 执行 → 产出 → 人工审核」构建，AI 产出必须完整呈现 `confidence / reasons / citations` 证据链（[接口规范 §4.1](../产品需求文档/页面级字段与接口文档/00-总览与接口规范.md)）。

## 3. 技术选型

| 领域 | 选型 | 版本基线 | 理由 |
|---|---|---|---|
| 框架 | Vue 3（Composition API + `<script setup>`） | 3.5+ | PRD §9 指定方向；生态成熟 |
| 语言 | TypeScript（strict） | 5.x | 类型安全的接口契约，团队已具备 TS 能力 |
| 构建 | Vite | 6+ | 快速冷启/热更，原生 ESM，分包能力强 |
| 路由 | Vue Router | 4.x | history 模式，路由级 code splitting |
| 客户端状态 | Pinia | 2.x | 官方推荐，TS 友好 |
| 服务端状态 | TanStack Query（vue-query） | 5.x | 列表缓存、轮询、失效、乐观更新——本应用重服务端状态，避免全塞 Pinia |
| UI 组件库 | Element Plus | 2.x | 中后台组件成熟（表格/表单/抽屉/分步），深色定制成本可控 |
| 样式 | SCSS + CSS Variables（Design Tokens） | — | 主题语义色统一入口，不引入额外原子 CSS 运行时 |
| 图表 | ECharts（按需注册）+ vue-echarts | 5.x | 折线/柱状/雷达/漏斗全覆盖（P1 数据中心） |
| 富文本/邮件编辑 | Tiptap | 2.x | contenteditable 内核，支持邮件草稿插入/编辑后批准 diff 场景 |
| SSE | @microsoft/fetch-event-source | 2.x | 原生 EventSource 不支持 `Authorization` 头与自定义重连，fetch 方案可控 |
| 工具库 | @vueuse/core、dayjs、lodash-es、dompurify | — | 组合式工具；时间渲染；富文本消毒 |
| i18n | vue-i18n | 9.x | MVP 支持 zh-CN / en（16 v0.4：org.defaultLanguage） |
| HTTP | axios | 1.x | 拦截器承载认证/错误码/traceId |
| Mock | MSW | 2.x | 按接口文档 schema 定义 handler，可同构单测复用 |
| 测试 | Vitest + @vue/test-utils + Playwright | — | 单测/组件测 + 主流程 E2E |
| 代码质量 | ESLint（flat config）+ Prettier + Stylelint + husky + lint-staged + commitlint | — | 提交期强制 |

## 4. 总体架构

```text
┌─────────────────────────────────────────────────────────────────┐
│ 视图层 Views（features/* 按模块划分，路由懒加载）                 │
│   dashboard / employee-center / lead-gen / customer-360 / crm   │
│   sales-workbench / follow-up / knowledge / approval / settings │
├─────────────────────────────────────────────────────────────────┤
│ 组件层 components                                                │
│   base（Element 二次封装 ProTable/PageContainer）                │
│   business（InsightCard / ApprovalCard / StreamLogPanel /       │
│             DraftEditor / ScopeSelect / Citations / ComingSoon） │
├─────────────────────────────────────────────────────────────────┤
│ 应用层 stores（Pinia：auth/app/dict/notify）                     │
│         composables（useAuth/usePermission/useTaskStream/       │
│                      usePolling/useUpload/useI18nFormat）        │
├─────────────────────────────────────────────────────────────────┤
│ 数据层 api（模块化 axios resources + 类型契约）                   │
│         query（vue-query keys/options 工厂）                     │
│         sse（fetch-event-source 封装，断线降级轮询）              │
├─────────────────────────────────────────────────────────────────┤
│ 基础设施 router（守卫链）· features.ts（编译期特性开关）          │
│           styles（tokens）· locales · directives · utils        │
└─────────────────────────────────────────────────────────────────┘
```

分层规则：

- **views 不直接 import axios**：一律经 `api/*` 与 vue-query，保证缓存/重试/失效统一；
- **business 组件不含接口调用**：入参出参均为 TS 类型，数据由视图层注入；
- **枚举零硬编码**：颜色/文案统一走 `dict` store 映射表（与[接口规范 §3](../产品需求文档/页面级字段与接口文档/00-总览与接口规范.md) 全局枚举对齐）。

## 5. 关键架构决策（ADR）

| # | 决策 | 理由与约束 |
|---|---|---|
| AD-1 | Vue 3 + TS + Vite 单应用工程，**不做 monorepo** | MVP 单团队单端；微前端/多端留待真实需求 |
| AD-2 | 服务端状态归 vue-query，Pinia 只放会话/偏好/字典/通知 | 列表缓存、`refetchInterval` 轮询、乐观更新是本应用高频诉求，Pinia 手写等价逻辑成本高 |
| AD-3 | SSE 用 `fetch-event-source` 统一封装 `useTaskStream` | 接口需 `Bearer` 头（接口规范 §2.1）；需自动重连 + 降级轮询 `/logs`（见 [03 §6](./03-状态管理与数据请求.md)） |
| AD-4 | P0/P1 边界用编译期常量 `features.ts`，随版本交付切换 | PRD 00 §5.1 明确「不做运行时功能开关 UI」；tree-shaking 可剔除 P1 死代码 |
| AD-5 | 邮件草稿编辑器基于 Tiptap 自研封装 | 「插入 AI 草稿」「编辑后批准」「insert_draft 内容型建议」都要求受控的可编程富文本，通用富文本组件过重 |
| AD-6 | 时间统一 dayjs 渲染为 org 时区/本地时区 | 数据库存 UTC、UI 按企业当地日历日（「今日待执行」口径，见工程约定） |
| AD-7 | AI 产出富文本一律 DOMPurify 消毒后渲染 | LLM 输出与会话邮件正文均为不可信输入，防存储型 XSS |
| AD-8 | 权限前端只做 UX 裁剪，服务端为唯一权威 | 越权以 `40301` 兜底（接口规范 §2.5/§4.4） |
