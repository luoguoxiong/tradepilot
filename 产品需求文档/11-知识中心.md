## 1. 模块定位

### 1.1 页面目标

企业知识的统一上传、分类、索引与检索（RAG 底座），为所有 AI 员工提供有据可依的知识来源：获客匹配、销售话术、报价依据、经营分析都从这里取数。

| FR-02 | 知识分类            | 全部 / 产品 / 公司 / 销售 / 客户 / FAQ（含流程知识等其他类别）                                                                   |

## 4. AI 行为边界

- **知识库是 AI 事实的唯一来源**：AI 引用知识时必须可追溯到具体文档；知识库无依据的问题，AI 应明确说「知识库中没有相关信息」，禁止编造。
- 索引失败要有明确提示与重试机制，不允许静默丢失知识。
- 知识删除 / 更新后，相关 AI 引用**实时同步失效**（检索直查向量库、无长缓存，见 §7）。

## 6. 效果指标（建议）

- 索引成功率与平均索引时长。
- 知识检索命中率：AI 回复中的引用能命中正确文档的比例。
- 「知识库无依据」提示率（异常高说明知识缺口，需引导补充上传）。

## 7. 待澄清问题

1. ~~支持的文件格式与大小上限；网页 / 邮件附件是否可一键入库。~~ → **已澄清**（v0.2）：
   - **格式白名单**：`pdf / docx / md / txt`（xlsx 等表格解析列后续增强）；**大小上限 50MB**，超限 `42201`。
   - **邮件附件一键入库：做**（FR-07）——[06 会话详情](./06-AI销售工作台.md) 附件「存入知识库」入口，转存后 `source='email_attachment'`，category 人工选（默认 `customer`）。
   - **网页抓取入库：不做**（清洗 / 反爬复杂度高，03 获客的 lead.website 信息不依赖知识库），列后续增强。
2. ~~知识的版本管理与更新策略（覆盖旧版 vs 多版本共存）。~~ → **已澄清**（v0.2）：**覆盖式更新，不做多版本共存**——更新 = 删除旧文档 + 上传新文档；AI 引用始终指向现存文档，RAG 语料保持唯一事实源，杜绝引用过期版本；重名文件不去重（各自独立行）。
   - **删除语义收口（v0.3.1，软删留痕）**：删除 = 旧文档行**软删**（`deleted_at / deleted_by`，行保留）+ 分块与向量随删动物理清除（检索天然不可命中，「引用实时失效」语义不变）；报价依据 / 草稿 / 审批 outputs 中引用的 docId 仍可回溯标题、分类、来源、上传人（展示标记「已删除」），审计可重建引用现场；覆盖式更新同样按此软删旧文档（新文档新 ID，引用不迁移）。见 [ER 06 §2.6](./PostgreSQL%20数据库%20ER%20图/06-产品与知识模块.md)。
3. ~~知识权限：是否按团队角色限制可见知识范围。~~ → **已澄清**（v0.2）：
   - **检索 / 引用 = org 级全量共享，不按角色过滤**——AI 员工必须能检索全部组织知识才能有据可依（「知识库是 AI 事实唯一来源」的前提）。
   - **上传 = 全员**（`uploaded_by` 记录贡献人）；**删除 / 重试 = 仅经理与管理员**（删除影响 AI 引用面，防误删，业务员返回 `40301`）。
   - 敏感分类（如客户知识按负责人可见）列后续增强。
